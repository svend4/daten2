# Рынок агентов · agent-to-agent (Agent Market)

Мультиагентность поверх магазина: **покупатель-агент** и **продавец-переговорщик**
торгуются по общему протоколу A2A и при согласии заключают сделку через **единый
контракт**. Правила переговоров задаёт **управляющий-агент** (пол цены, максимальная
скидка, опт). «Магазин, которым говорят» → **рынок агентов**: третьи стороны могут
писать своих агентов под тот же протокол/контракт.

```
управляющий (политика: пол, макс.скидка, опт)
        │
        ▼
покупатель-агент  ⇄  протокол A2A (ask/bid/accept/reject)  ⇄  продавец-переговорщик
        └──────────── сделка ──────────────▶ единый контракт /api/orders
```

## Протокол A2A

Агенты обмениваются типизированными сообщениями `{ round, from, type, price, note }`,
тип ∈ `greet · ask · bid · accept · reject`. Продавец открывает прайсом, покупатель
контрит снизу; стороны уступают навстречу и сходятся, когда разрыв закрывается —
или расходятся за `maxRounds`.

## Экономика (детерминированное ядро)

- **Пол продавца** = `прайс × (1 − maxDiscount − оптовый бонус)` — ниже не опускается.
- **Потолок покупателя** = `min(бюджет/ед, прайс)`.
- **ZOPA** (зона сделки) существует ⇔ бюджет ≥ пола → торг **сходится** к цене в
  `[пол, потолок]`; иначе — **сделки нет**.
- **Опт**: количество ≥ порога двигает пол ниже (дополнительная скидка).

Сделка гарантированно **не ниже пола** и **не выше прайса**; скидка в пределах политики.

## Два движка агентов, одна политика

Без ключа — детерминированные стратегии уступок. С `ANTHROPIC_API_KEY` роль
покупателя/продавца может играть **Claude** (`claude-opus-4-8`), но цена **жёстко
ограничена** полом/потолком — LLM не может нарушить политику. Демо и тесты работают
без ключа.

## Запуск

```bash
npm install
export BACKEND_URL=http://localhost:8080   # роутер или любой уровень
export MAX_DISCOUNT=0.2                      # максимум уступки от прайса
npm start                                    # → http://localhost:8078
```

Дашборд: выбор товара/количества/бюджета, кнопка «Запустить торг» — переговоры
разворачиваются как чат двух агентов, внизу — итог сделки и номер заказа.

## API

| Метод | Путь | Назначение |
|-------|------|------------|
| `GET`  | `/api/health`   | `{ ok, engine, backend, policy }` |
| `GET`  | `/api/catalog`  | каталог (для выбора товара) |
| `POST` | `/api/negotiate`| `{ productId, quantity, buyerBudget }` → `{ deal, transcript, order }` |
| `GET`  | `/api/history`  | последние переговоры + статистика |
| `POST` | `/api/ask`      | сводка по переговорам |

## Переменные окружения

| Переменная | По умолчанию | Назначение |
|------------|--------------|------------|
| `BACKEND_URL` | `http://localhost:8080` | Бэкенд единого контракта |
| `MAX_DISCOUNT` | `0.2` | Максимальная уступка от прайса |
| `MAX_ROUNDS` | `8` | Предел раундов торга |
| `BULK_THRESHOLD` / `BULK_BONUS` | `10` / `0.05` | Порог опта и доп. скидка |
| `ANTHROPIC_API_KEY` / `ANTHROPIC_MODEL` | — / `claude-opus-4-8` | LLM-агенты |
| `PORT` | `8078` | Порт |

## Тест

```bash
npm test
```

`test/smoke.mjs` проверяет: сходимость при наличии ZOPA, отсутствие сделки без ZOPA,
соблюдение пола и границ скидки, оптовую доп. скидку, чередование сторон, и HTTP —
достигнутая сделка оформляется через контракт, а несостоявшаяся заказ не создаёт.
Без сети и ключа. 15/15.
