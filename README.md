# Carbon arbitrage — углеродно-осознанное планирование ♻️🌷

Временной и пространственный **арбитраж углеродного следа**: сдвигает отложимые ИИ-нагрузки (батч-эмбеддинги, ночная дистилляция, переиндексация) в самые **зелёные** и **дешёвые** окна энергосети — по времени (когда сеть чище) и по регионам (куда можно унести вычисление) — с учётом дедлайнов и ёмкости. Считает измеримый выигрыш CO₂ и денег против наивного «всё сейчас, дома».

> Часть системы [flower-shop / 7 уровней](https://github.com/svend4/daten2). Развитие идеи green-роутера (`:8093`): тот выбирает уровень **мгновенно** per-request; carbon arbitrage **планирует** портфель отложимой работы **во времени и пространстве**.

## Чем отличается от green-роутера

| | green-router `:8093` | carbon-arbitrage `:8107` |
|---|---|---|
| Решение | какой уровень **сейчас** | в какое **окно (регион × слот)** сдвинуть работу |
| Горизонт | мгновенный, per-request | прогноз сети на T слотов вперёд |
| Ось | пространство (уровни) | **время + пространство** (слоты × регионы) |
| Ограничения | веса метрик | + **дедлайны**, **ёмкость** окон, **резидентность** данных |
| Выход | выбранный уровень | план-расписание + **арбитражный выигрыш** vs baseline |

## Как это работает

1. **Прогноз сети** (`grid.js`) — регионы × слоты с углеродоёмкостью (гCO₂/кВт·ч) и ценой (€/кВт·ч). Пространственный арбитраж (eu-north чистый, us-east дешёвый но грязный) + временной (суточная синусоида) создают окна выгоды.
2. **Нагрузки** — каждая: энергия (кВт·ч), **дедлайн** (слот, до которого надо выполнить), допустимые регионы (**резидентность**), флаг `deferrable`. Неотложимые пришпилены к «сейчас».
3. **Планировщик** (`scheduler.js`) — жадность least-flexible-first: сначала размещаем работы с жёстким дедлайном, гибкие добирают оставшуюся **зелёную ёмкость**. Каждая работа уходит в окно с минимальной смешанной метрикой `carbon/price` среди доступных по ёмкости; «сейчас, дома» всегда доступно как fallback → углерод никогда не хуже наивного (при углеродной цели).
4. **Арбитраж** (`arbitrage.js`) — оптимизированный план против наивного baseline → сэкономленные CO₂ и € (абсолют и %).
5. **Инварианты** (`invariants.js`) — дедлайны соблюдены, регионы допустимы, ёмкость окон не превышена, углерод ≤ наивного.
6. **Два движка**: без ключа — детерминированный планировщик. С `ANTHROPIC_API_KEY` — **LLM-советник** (`claude-opus-4-8`): агрессивнее сдвигать / ослабить дедлайны / докупить зелёную ёмкость.

## API

| Метод | Путь | Назначение |
|---|---|---|
| GET  | `/api/health` | движок, число слотов, регионы |
| GET  | `/api/grid` | прогноз сети (регионы × слоты) |
| POST | `/api/schedule` | `{jobs:[{id,energy,deadline,deferrable,regions}], weightCarbon?, capacityPerCell?}` → план + выигрыш + инварианты |
| GET  | `/api/last` | последний план |
| POST | `/api/ask` | объяснение словами (выигрыш, сдвиги) |

`weightCarbon`: 1 — чистый углерод, 0 — чистая цена, между — смешанная цель.

## Запуск

```bash
npm install
npm test                 # 13 проверок: планы корректны под 60 случайными нагрузками + сдвиг/дедлайн/ёмкость/цель + HTTP
node server.js           # :8107, дашборд на /
```

Дашборд (`/`): тепловая карта сети (регион × слот, гCO₂) с наложенными размещёнными работами, ползунок цель CO₂↔цена, ёмкость окна, экономия CO₂/€, таблица размещений (было→стало).

## Переменные окружения

| Переменная | Смысл |
|---|---|
| `PORT` | порт (по умолчанию 8107) |
| `SLOTS` | горизонт планирования в слотах (по умолчанию 12) |
| `ANTHROPIC_API_KEY` | включает LLM-советник по стратегии |

Смоук-тест — property-style: 60 случайных наборов нагрузок, и для каждого плана проверяется, что все дедлайны/регионы/ёмкость соблюдены и углерод ≤ наивного. Плюс точечно: отложимая работа уходит в зелёный регион, дедлайн 0 мешает сдвигу, малая ёмкость раскладывает работы по разным окнам, неотложимая пришпилена к «сейчас», а ценовая цель выбирает другое окно, чем углеродная.
