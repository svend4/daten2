# Самооптимизирующийся роутер (Router + ML)

Капабилити-роутер, который выбирает уровень магазина **не по статичной политике, а
по онлайн-модели**: для каждого запроса он оценивает уровни по измеренной
латентности, надёжности, стоимости и текущей нагрузке — и учится на реальных
исходах. Все уровни говорят на **едином контракте**, поэтому взаимозаменяемы; ML
превращает их набор в **самооптимизирующуюся композицию**.

```
запрос → [мозг: utility + разведка UCB] → лучший уровень → замер → обучение
                         ↑___________ обратная связь (латентность, исход) __________|
```

## Как выбирается уровень (ML-ядро)

Для каждого уровня модель держит скользящие оценки и обновляет их после **каждого**
ответа:

| Сигнал | Обновление |
|--------|-----------|
| `latencyEwma` | экспоненциальное среднее измеренной латентности (по успехам) |
| `successEwma` | экспоненциальное среднее исхода (1 — успех, 0 — ошибка) |
| `inflight` | текущее число одновременных запросов (реальная нагрузка) |
| `cost` | относительная стоимость уровня (задаётся) |

**Полезность** уровня — выше для быстрого, надёжного, дешёвого и незагруженного:

```
utility = successEwma · (latencyCap / (latencyCap + latencyEwma)) / cost / (1 + inflight·loadPenalty)
```

**Выбор — UCB1**: `score = utility + c·√(ln N / (nᵢ+1))`. Эксплуатируем лучший
уровень, но бонус разведки заставляет иногда пробовать недоисследованные — так
роутер **замечает изменения** нагрузки/стоимости/деградацию, а не застревает на
устаревшем решении. При сбое выбранного уровня — **failover** на следующий по
полезности.

Это и есть «ML»: не оффлайн-обучение, а онлайн-оценка (contextual bandit),
сходящаяся к оптимуму и адаптирующаяся в реальном времени.

## Что демонстрирует смоук-тест

Три уровня — A (быстрый, дешёвый), B (медленный, дешёвый), C (быстрый, дорогой):

- **Норма** → трафик сходится к A: `{A:37, B:3}` из 40 (A — лучший по латентности×цене).
- **Деградация A** (начал падать и тормозить) → трафик уходит на B: `{B:40}`, при
  этом **все 40 запросов успешны** благодаря failover, а решение роутера
  автоматически сменяется с A на B.

То есть роутер маршрутизирует по **выученной** надёжности/скорости, а не по
статичному списку приоритетов и даже не по одному лишь `/api/health`.

## Два движка объяснений, одно ядро

`POST /api/ask` — оператор спрашивает о решениях роутера:

| Движок | Когда | Что делает |
|--------|-------|------------|
| **`llm`** (Claude API) | задан `ANTHROPIC_API_KEY` | Claude объясняет выбор, беря живую статистику **только** из инструмента `router_stats` (`claude-opus-4-8`) |
| **`rules`** | ключа нет | Детерминированные ответы: почему выбран, сравнение, проблемные уровни |

Само ML-ядро маршрутизации всегда детерминировано; LLM лишь озвучивает решения.

## Запуск

```bash
npm install
# уровни-кандидаты (иначе локальные значения по умолчанию):
export ROUTER_BACKENDS='[{"id":"level1","name":"PHP","url":"http://localhost:8081","cost":1},
                         {"id":"level6","name":"Next.js","url":"http://localhost:8086","cost":3}]'
# export ANTHROPIC_API_KEY=sk-ant-...   # включить LLM-объяснения
npm start                                # → http://localhost:8073
```

Дашборд: таблица уровней с полезностью/латентностью/надёжностью в реальном
времени, кнопка «прогнать N запросов» показывает распределение трафика, чат —
вопросы роутеру.

## API

| Метод | Путь | Назначение |
|-------|------|------------|
| `GET`  | `/api/health`          | `{ ok, engine, backends }` |
| `GET`  | `/api/router/stats`    | решение + метрики по уровням |
| `GET`  | `/api/router/decide`   | сухой прогон: какой уровень и почему |
| `POST` | `/api/router/refresh`  | опросить `/api/health` уровней |
| `POST` | `/api/ask`             | `{ sessionId, message }` → объяснение |
| `ALL`  | `/api/products`, `/api/orders`, `/api/orders/:id` | проксирование контракта на выбранный уровень (заголовок `X-Served-By-Level`) |

## Переменные окружения

| Переменная | По умолчанию | Назначение |
|------------|--------------|------------|
| `ROUTER_BACKENDS` | локальные L1/L2/L5/L6 | Уровни-кандидаты (JSON) |
| `LATENCY_CAP_MS` / `EXPLORE_C` / `LOAD_PENALTY` / `EWMA_ALPHA` | `500` / `0.3` / `0.5` / `0.3` | Параметры модели и разведки |
| `HEALTH_MS` / `PROXY_TIMEOUT_MS` | `15000` / `5000` | Период health-опроса; таймаут прокси |
| `ANTHROPIC_API_KEY` / `ANTHROPIC_MODEL` | — / `claude-opus-4-8` | LLM-объяснения |
| `PORT` | `8073` | Порт |

## Тест

```bash
npm test
```

`test/smoke.mjs` поднимает три управляемых mock-уровня и проверяет сходимость
трафика к лучшему, уход трафика и failover при деградации, смену решения и падение
надёжности проблемного уровня. Без сети и ключа. 12/12.
