# daten2 — «магазин цветов» в семи уровнях + AI-слой

Один магазин, реализованный на **семи возрастающих по сложности стеках**, объединённый
**единым контрактом** (`/api/health`, `/api/products`, `/api/orders`,
`/api/orders/{token}`), и надстроенный **самооптимизирующимся роутером** и **слоем
ИИ**. `docker-compose.yml` сводит всё в один живой стенд.

## Семь уровней (живые бэкенды)

| Уровень | Стек | Ветка-первоисточник |
|---------|------|---------------------|
| L1 | PHP + SQLite | `claude/level1-php-GBpVR` |
| L2 | Flask + SQLite | `claude/level2-flask-GBpVR` |
| L3 | Django | `claude/level3-django-GBpVR` |
| L4 | Node/Express + EJS | `claude/level4-express-GBpVR` |
| L5 | React (Vite) + Flask API | `claude/level5-react-flask-GBpVR` |
| L6 | Next.js + Prisma + PostgreSQL | `claude/level6-nextjs-GBpVR` |
| L7 | Микросервисы (Node + Python + RabbitMQ + PostgreSQL + nginx) | `claude/level7-enterprise-GBpVR` |

Все семь говорят на одном контракте, поэтому **взаимозаменяемы**.

## Слой поверх уровней

| Компонент | Роль | Ветка |
|-----------|------|-------|
| **Роутер** | Самооптимизирующийся выбор уровня (латентность/стоимость/нагрузка/надёжность, UCB + failover) | `claude/ai-router-GBpVR` |
| **Витрина** | Разговорная торговля: ИИ продаёт покупателю через контракт | `claude/ai-storefront-GBpVR` |
| **Управляющий** | Спрос, дозаказ, цены, аномалии из просадки остатков | `claude/ai-manager-GBpVR` |
| **Поиск** | Семантический поиск по смысловым осям + рекомендации | `claude/ai-search-GBpVR` |
| **Общие сервисы** | auth + payment (реализованы один раз для всех) | `claude/gateway-router-GBpVR` |

Витрина, управляющий и поиск ходят в магазин **через роутер**, поэтому прозрачно
используют самый здоровый уровень.

## Топология стенда

```
                       ┌─── витрина (8070) ───┐
   покупатель ─┐       ├─── управляющий (8071)┤   все три — через роутер
               ▼       └─── поиск (8072) ──────┘
        роутер :8080  ── /api/health опрос ──▶  L1 L2 L3 L4 L5 [L6] [L7]
        (UCB + failover)  ── контракт ───────▶   (выбирает лучший, обходит упавший)
```

## Быстрый старт

```bash
cp .env.example .env        # при желании впишите ANTHROPIC_API_KEY

# базовый стенд: L1–L5 + роутер + витрина + управляющий + поиск
docker compose up --build

# добавить L6 (Next.js + PostgreSQL + сид):
docker compose --profile full up --build

# добавить L7 (микросервисы + RabbitMQ + PostgreSQL + nginx):
docker compose --profile enterprise up --build

# добавить общие сервисы auth + payment:
docker compose --profile commerce up --build

# всё сразу:
docker compose --profile full --profile enterprise --profile commerce up --build
```

Сборка идёт **из веток-первоисточников** (git build-context) — код не дублируется,
`docker-compose.yml` и есть единая точка сборки. Для приватного репозитория укажите
доступный `REPO` в `.env` (или сделайте репозиторий публичным).

### Порты

| URL | Что |
|-----|-----|
| http://localhost:8080 | **Роутер** (главный вход, единый контракт) + дашборд трафика |
| http://localhost:8070 | Разговорная витрина |
| http://localhost:8071 | Дашборд управляющего |
| http://localhost:8072 | Семантический поиск |
| http://localhost:8081…8087 | Уровни L1…L7 напрямую (для отладки) |
| http://localhost:8091 / 8092 | auth / payment (профиль commerce) |

`ANTHROPIC_API_KEY` (необязателен): с ним роутер/витрина/управляющий/поиск включают
LLM-движки (Claude, `claude-opus-4-8`); без него работают в детерминированном режиме
— стенд полностью функционален и без ключа.

## Профили

| Профиль | Добавляет |
|---------|-----------|
| *(по умолчанию)* | L1–L5, роутер, витрина, управляющий, поиск |
| `full` | L6 (`l6-db` PostgreSQL, `l6-seed` разовый сид, `level6`) |
| `enterprise` | L7 (`l7-postgres`, `l7-rabbitmq`, `product-service`, `order-service`, `notification-service`, `level7` nginx) |
| `commerce` | `auth`, `payment` |

Роутер знает про все семь уровней; отсутствующие (профиль не поднят) он видит как
offline и маршрутизирует в остальные — это и демонстрирует его устойчивость.

## Проверка оркестрации

Живой прогон в контейнерах подтвердил сквозной путь: **витрина → роутер → живой
уровень** — диалоговый заказ проходит и приземляется на уровень; при остановке
выбранного уровня роутер **на лету переключает** трафик на следующий (failover), заказы
продолжают оформляться. `docker compose config` валиден для всех профилей (20 сервисов).

> Примечание: в песочнице-CI полная сборка образов уровней невозможна (менеджеры
> пакетов apt/pip/npm не проходят TLS через самоподписанный прокси) — это ограничение
> среды, а не стенда. Каждый компонент независимо покрыт своим smoke-тестом
> (роутер 12/12, витрина 19/19, управляющий 19/19, поиск 16/16, контракт 22/22).

## Файлы стенда

| Файл | Роль |
|------|------|
| `docker-compose.yml` | Единая сборка: 7 уровней + роутер + AI + общие сервисы (профили) |
| `.env.example` | `REPO`, `ANTHROPIC_API_KEY`, `AUTH_SECRET` |
| `stack/level7/nginx.conf` | API-gateway L7 (только контракт, без витрины L7) |
| `stack/level7/db-init.sql` | Каноническая схема + сид для PostgreSQL L7 |
| `flower_shop_levels/` | Исходный код семи уровней (source-of-record) |
