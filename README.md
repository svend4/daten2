# Rosetta — кросс-языковой верификатор портов 🪨🌷

**Differential conformance** для семи языковых реализаций одного контракта. Обычные контрактные тесты проверяют каждую реализацию против *статичной спецификации*. Rosetta проверяет реализации **друг против друга**: прогоняет один и тот же сценарий контракта против всех портов и ловит расхождения наблюдаемого поведения между языками — класс багов «PHP округляет сумму иначе, чем Django», который per-implementation тесты не видят.

> Часть системы [flower-shop / 7 уровней](https://github.com/svend4/daten2). Семь стеков (PHP, Flask, Django, Express, React+API, Next.js, микросервисы) реализуют один REST-контракт — значит, обязаны вести себя одинаково. Rosetta это доказывает или опровергает с точным путём до расхождения.

## Чем отличается от соседей по системе

| Сервис | Что сравнивает |
|---|---|
| **contract-CDC** | каждую реализацию против **статичного Pact** (по отдельности) |
| **shadow/canary** | кандидат-версию против **текущей той же** реализации |
| **observability** | **производительность** 7 стеков (p50/p95/p99) |
| **Rosetta** | реализации **между собой** — N-way дифференциальная эквивалентность **поведения** |

## Как это работает

1. **Один сценарий контракта** (`runner.js`) — детерминированная последовательность: `health` → `products` → `create-order` → `get-order`, прогоняется против каждого порта.
2. **Семантическая проекция** (`project.js`) — здесь закодировано, *что обязано совпадать* (набор товаров, цены, сумма заказа, статус, состав) и *что вправе различаться* (метка уровня в health, внутренние id, картинки, токен заказа, метки времени). Волатильные поля нормализуются — иначе каждый порт «расходился» бы на них без реальной причины.
3. **N-way diff против эталона** (`diff.js`) — один порт берётся эталоном (oracle), остальные сверяются с ним пошагово; расхождение возвращается с точным путём (`products[0].price`, `get-order.status`).
4. **Baseline-waiver** (`runner.compare`) — зафиксируйте текущие расхождения как *принятые* (например, осознанные различия портов); тогда повторная сверка покажет только **новые** расхождения — регрессии совместимости.
5. **Два движка**: без ключа — детерминированный diff. С `ANTHROPIC_API_KEY` подключается **LLM-классификатор** (`claude-opus-4-8`): баг реализации / дрейф данных / допустимая вариация + severity.

## Что проверяется на каждом шаге

| Шаг | Обязано совпадать | Нормализуется (вправе различаться) |
|---|---|---|
| `health` | живость (`ok`) | метка уровня (у каждого своя) |
| `products` | имя · цена · активность (сорт. по имени) | id, картинки, порядок выборки |
| `create-order` | сумма · факт выдачи токена | сам токен заказа |
| `get-order` | статус · состав (имя/кол-во/цена) · сумма | токен, метки времени |

## API

| Метод | Путь | Назначение |
|---|---|---|
| GET  | `/api/health` | движок (`rules`/`llm`), число портов |
| GET  | `/api/backends` | список портов по умолчанию |
| POST | `/api/verify` | `{backends?, referenceName?}` → матрица эквивалентности + расхождения |
| POST | `/api/baseline` | принять текущие расхождения как baseline (waiver) |
| GET  | `/api/last` | последний прогон |
| POST | `/api/ask` | `{message}` → объяснение расхождений словами |

Каждый порт — реализация контракта `GET /api/health`, `GET /api/products`, `POST /api/orders`, `GET /api/orders/{order_number}`.

## Запуск

```bash
npm install
npm test                 # 17 проверок через реальный HTTP: 3 эквивалентных порта + 1 расходящийся
node server.js           # :8103, дашборд на /
# список портов через окружение:
ROSETTA_BACKENDS='[{"name":"php","url":"http://localhost:8081"},{"name":"flask","url":"http://localhost:8082"}]' node server.js
```

Дашборд (`/`): матрица портов (эталон / эквивалентен / расходится), таблица расхождений с путём и парой значений эталон≠порт, фиксация baseline, баннер нарушения совместимости.

## Переменные окружения

| Переменная | Смысл |
|---|---|
| `PORT` | порт (по умолчанию 8103) |
| `ROSETTA_BACKENDS` | JSON-список портов `[{name,url}]` |
| `ANTHROPIC_API_KEY` | включает LLM-классификатор расхождений |
| `ROSETTA_TIMEOUT_MS` | таймаут запроса к порту (8000) |

Смоук-тест поднимает 4 mock-порта одного контракта: три ведут себя одинаково (разные «языки» с идентичным поведением), четвёртый расходится (завышена цена розы → каскадом сумма заказа + иной статус). Проверяется, что эквивалентные признаны одинаковыми, расходящийся пойман с точным путём, а baseline-waiver показывает только новые расхождения.
