# Property-based инварианты контракта (Property Tests)

Тестирование **свойств, а не примеров**: харнесс **генерирует случайные валидные
входы** (заказы со случайными позициями и количествами, случайные токены) и проверяет,
что **инварианты контракта держатся на всех** сгенерированных случаях против любого
уровня. При провале — **сжатие (shrinking)** до минимального контрпримера.

```
для каждого свойства: генератор → N случайных входов → проверка инварианта
                       первый провал → shrink → минимальный контрпример
```

## Инварианты (свойства)

| Свойство | Инвариант |
|----------|-----------|
| `total-invariant` | `total = Σ (цена × количество)` для любого заказа |
| `order-retrievable` | заказ находится по своему токену |
| `token-privacy` | **невыданный токен → не отдаёт заказ** (нет IDOR) |
| `distinct-tokens` | разные заказы → разные токены |
| `read-idempotent` | `GET /api/products` идемпотентен |

Каждое проверяется на десятках случайных входов — это ловит баги, которые
пример-ориентированные тесты пропускают.

## Генерация и сжатие

- **Генераторы** (`gen.js`) — детерминированный ГПСЧ (seed): случайный заказ
  (1..3 разных товара, кол-во 1..5), случайный «фейковый» токен.
- **Сжатие** (`shrink`) — при провале харнесс уменьшает вход (убирает позиции,
  делит количества) пока свойство продолжает падать → **минимальный контрпример**
  (напр. «1 позиция, количество 1»), который легко воспроизвести и отладить.
- **Детерминизм** — один seed → тот же прогон и тот же контрпример.

## Запуск

```bash
npm install
export TARGET_URL=http://localhost:8080   # цель (роутер/уровень)
npm start                                  # → http://localhost:8098
```

Дашборд: цель, число входов и seed, таблица свойств (держится / FAIL) с показом
сжатого контрпримера.

## API

| Метод | Путь | Назначение |
|-------|------|------------|
| `GET`  | `/api/health` / `/api/properties` | статус и список свойств |
| `POST` | `/api/run` | `{ target, iterations, seed }` → прогон + контрпримеры |
| `GET`  | `/api/last` | последний прогон |
| `POST` | `/api/ask` | сводка/контрпримеры |

## Переменные окружения

| Переменная | По умолчанию | Назначение |
|------------|--------------|------------|
| `TARGET_URL` | `http://localhost:8080` | Цель проверки |
| `PROP_TIMEOUT_MS` | `5000` | Таймаут запроса |
| `ANTHROPIC_API_KEY` / `ANTHROPIC_MODEL` | — / `claude-opus-4-8` | LLM-сводка |
| `PORT` | `8098` | Порт |

## Тест

```bash
npm test
```

`test/smoke.mjs` проверяет: на **исправном** провайдере все 5 свойств держатся; на
**сломанных** конкретное свойство падает — нарушение `total` (с контрпримером,
**сжатым до 1 позиции, кол-во 1**), IDOR (нарушена приватность токена),
неидемпотентный каталог; и **детерминизм** (один seed → тот же контрпример). Без сети
и ключа. 12/12.

## Файлы

| Файл | Роль |
|------|------|
| `gen.js` | ГПСЧ + генераторы случайных входов |
| `properties.js` | Свойства-инварианты (генератор + проверка + shrink) |
| `runner.js` | Движок: прогон на входах + сжатие контрпримера |
| `http.js` | HTTP-клиент к цели |
| `interpret.js` / `store.js` | Сводка и последний прогон |
| `server.js` | Express: `/api/run`, `/api/properties` |
| `public/index.html` | Дашборд свойств и контрпримеров |
| `test/smoke.mjs` | Смоук-тест свойств и сжатия |
