# Цифровой двойник магазина (Digital Twin)

Живая симуляция магазина: **синтетические покупатели генерируют спрос через тот же
единый контракт**, что и настоящие. Двойник (1) моделирует поток посетителей и их
решения во времени, (2) отвечает на **what-if** («что будет с выручкой, если поднять
цены на 20%?»), (3) в «живом» режиме **оформляет реальные заказы** через контракт —
и тем самым кормит роутер, наблюдаемость и управляющего, замыкая контур.

```
сегменты покупателей ─решения(спрос↔цена)→ единый контракт (/api/products, /api/orders)
        ▲                                              │
        └──────── what-if / живой трафик ──────────────┘  → роутер · наблюдаемость · управляющий
```

## Модель спроса

Поток посетителей идёт по **суточной волне**; каждый посетитель принадлежит сегменту
и принимает решение о покупке:

| Сегмент | Бюджет | Чувствительность к цене | Тяга |
|---------|:------:|:-----------------------:|------|
| Романтик | высокий | низкая | розы, ★ |
| Экономный | низкий | высокая | тюльпаны |
| Организатор | средний | средняя | пионы, крупные заказы |
| Зевака | средний | средняя | редко покупает |

**Реакция спроса на цену встроена**: вероятность покупки падает по мере приближения
цены к бюджету сегмента → поднимаешь цену — конверсия снижается (классическая кривая
спроса). Поэтому двойник — инструмент для **офлайн-проверки стратегий** до реального
магазина.

Симуляция **детерминирована по seed** (ГПСЧ mulberry32): один seed → повторяемый
прогон, честное сравнение сценариев.

## Три режима

| Режим | Эндпоинт | Что делает | Побочки |
|-------|----------|-----------|:-------:|
| **Симуляция** | `POST /api/simulate` | поток → решения → метрики (конверсия, выручка, AOV, по товарам/сегментам, ряд по тикам) | нет |
| **What-if** | `POST /api/whatif` | база vs ценовой множитель → Δвыручка, Δконверсия | нет |
| **Живой** | `POST /api/run-live` | те же решения, но **реальные заказы** через `/api/orders` | да (заказы) |

Живой режим — это генератор нагрузки: направьте `BACKEND_URL` на **роутер**, поднимите
рядом **управляющего** и **наблюдаемость** — двойник создаёт спрос, управляющий видит
просадку остатков и реагирует ценами/дозаказом, роутер балансирует, наблюдаемость мерит.
Получается **замкнутый самонастраивающийся контур**.

## Два движка интерпретации, одно ядро

`POST /api/ask`: с `ANTHROPIC_API_KEY` — Claude-аналитик (числа только из инструмента
`twin_results`, `claude-opus-4-8`); без ключа — детерминированные ответы (итоги,
сегменты, бестселлеры, what-if). Ядро симуляции всегда детерминировано.

## Запуск

```bash
npm install
export BACKEND_URL=http://localhost:8080   # роутер или любой уровень
# export ANTHROPIC_API_KEY=sk-ant-...        # включить LLM-аналитика
npm start                                    # → http://localhost:8075
```

Дашборд: параметры прогона, кнопки «Симуляция» / «Живой прогон» / «Сравнить с базой»
(what-if), KPI, кривая выручки по тикам, продажи по товарам и сегментам, чат с аналитиком.

## API

| Метод | Путь | Назначение |
|-------|------|------------|
| `GET`  | `/api/health`   | `{ ok, engine, backend, hasRun }` |
| `GET`  | `/api/personas` | сегменты покупателей |
| `POST` | `/api/simulate` | `{ ticks, arrivalRate, seed, priceMultiplier, onlyPersona }` → метрики |
| `POST` | `/api/whatif`   | `{ ..., multiplier }` → база vs сценарий |
| `POST` | `/api/run-live` | живой прогон: реальные заказы через контракт |
| `GET`  | `/api/state`    | последний прогон |
| `POST` | `/api/ask`      | интерпретация результатов |

## Переменные окружения

| Переменная | По умолчанию | Назначение |
|------------|--------------|------------|
| `BACKEND_URL` | `http://localhost:8080` | Бэкенд единого контракта (роутер/уровень) |
| `ANTHROPIC_API_KEY` / `ANTHROPIC_MODEL` | — / `claude-opus-4-8` | LLM-аналитик |
| `PORT` | `8075` | Порт |

## Тест

```bash
npm test
```

`test/smoke.mjs` проверяет: детерминизм (один seed → идентичный прогон), реакцию
спроса на цену (наценка снижает конверсию), поведение сегментов (экономный → тюльпаны,
романтик → розы), HTTP `/api/simulate` и `/api/whatif`, а также **живой режим** —
реальные заказы приземляются на mock-бэкенд. Без сети и ключа. 16/16.
