# Событийная шина · event sourcing (Event Bus)

Единый **append-only поток доменных событий** магазина: заказы, смены статусов,
изменения остатков и цен. События приходят двумя путями — **push** (уровни/сервисы
публикуют напрямую) и **pull-деривация** (шина сравнивает снимки каталога и рождает
`StockChanged`/`PriceChanged` даже там, где уровень их не публикует). Поверх журнала —
**проекции-read-models** (свёртка) и **SSE-поток** для аналитики и ИИ.

```
push  (POST /api/events) ──┐
                           ├──▶ [журнал: append-only] ──swёртка──▶ проекции (read-models)
pull  (снимок каталога) ───┘                          └──stream──▶ SSE (аналитика/ИИ)
                                                       (rebuild = повторная свёртка)
```

## Event store (источник истины)

Журнал только **дополняется**: событие `{ seq, type, at, source, payload }` с
монотонным `seq`. Прошлые события **неизменны**. Реплей: `GET /api/events?from=seq`.
Типы: `OrderPlaced · OrderStatusChanged · StockChanged · PriceChanged ·
ProductAdded · ProductRemoved · ProductViewed`.

## Проекции = свёртка событий

Read-models строятся как `fold(events)`: заказы и **выручка** (сумма `OrderPlaced`),
таймлайн остатков, история цен, счётчики по типам. Ключевое свойство event sourcing —
проекции **пересобираемы** из журнала (`POST /api/rebuild`), детерминированно.

## Деривация из контракта

Единый контракт read-mostly, поэтому `POST /api/snapshot` тянет `/api/products`,
сравнивает с прошлым снимком и **порождает события** из разницы. Так поток
наполняется реальными изменениями без доработки уровней (как управляющий выводит
спрос из просадки остатков).

## Единый поток (SSE)

`GET /api/stream` — Server-Sent Events: каждое новое событие уходит подписчикам
(`event: <Type>`, `data: <json>`). Это тот самый «один поток», которым питаются
аналитика, ИИ-управляющий и наблюдаемость — без опроса каждого уровня.

## Запуск

```bash
npm install
export BACKEND_URL=http://localhost:8080   # источник для деривации (роутер/уровень)
npm start                                   # → http://localhost:8097
```

Дашборд: проекции (события/заказы/выручка/смены цен), кнопки «снимок → события»,
«пересобрать», «опубликовать заказ», и живой SSE-поток событий.

## API

| Метод | Путь | Назначение |
|-------|------|------------|
| `GET`  | `/api/health` | статус + типы событий |
| `POST` | `/api/events` | опубликовать событие (push) |
| `GET`  | `/api/events?from=` | журнал / реплей |
| `GET`  | `/api/projections` | read-models (свёртка) |
| `POST` | `/api/rebuild` | пересобрать проекции из журнала |
| `POST` | `/api/snapshot` | снимок каталога → деривация событий |
| `GET`  | `/api/stream` | единый поток событий (SSE) |
| `POST` | `/api/ask` | сводка по потоку |

## Переменные окружения

| Переменная | По умолчанию | Назначение |
|------------|--------------|------------|
| `BACKEND_URL` | `http://localhost:8080` | Источник деривации |
| `ANTHROPIC_API_KEY` / `ANTHROPIC_MODEL` | — / `claude-opus-4-8` | LLM-аналитик потока |
| `PORT` | `8097` | Порт |

## Тест

```bash
npm test
```

`test/smoke.mjs` проверяет: append-only журнал (монотонный seq, неизменность,
реплей), свёртку проекций (выручка = Σ `OrderPlaced`) и **детерминированный
rebuild**, деривацию из снимков (`StockChanged`/`PriceChanged`/`ProductAdded`/
`ProductRemoved`), живой **SSE-поток**, и HTTP. Без сети и ключа. 17/17.
