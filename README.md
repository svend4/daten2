# Контракт codegen + CDC · Pact (Contract CDC)

Машинная гарантия взаимозаменяемости уровней. Из **одной спецификации** контракта
генерируются **типизированные клиенты** (JS / Python / TS-типы), а **consumer-driven
contract** (пакт) верифицирует, что **любой уровень** удовлетворяет ожиданиям
потребителя. Это превращает «уровни взаимозаменяемы» из обещания в **проверяемый
факт**.

```
spec.js ─┬─codegen─▶ JS / Python / TS-клиенты (потребители)
         └──pact───▶ верификация провайдера (уровня) → pass/fail по взаимодействиям
```

## Codegen из спецификации

`spec.js` описывает операции и типы контракта. `GET /api/codegen?lang=…`
генерирует клиент:

- **`js`** — класс `FlowerShopClient` с async-методами (`listProducts`, `createOrder`, …);
- **`python`** — тот же клиент со snake_case-методами (`create_order`, …);
- **`ts-types`** — TypeScript-интерфейсы (`Product`, `Order`, …) из типов контракта.

Один источник → согласованные клиенты для всех семи уровней. Сгенерированный код
реально исполняется (тест инстанцирует JS-клиент).

## CDC · Pact-верификация

`pact.js` — это **ожидания потребителя** (фронтенд/AI-слой) к любому провайдеру:
набор взаимодействий с **типовыми матчерами** (Pact-style «like») — сравнивается
**структура и типы**, а не значения. Поэтому изменчивый `order_number` проходит по
типу `string`, а лишние поля провайдера допускаются (совместимость вперёд).

`POST /api/verify {target}` проигрывает каждое взаимодействие против уровня
(с подстановкой захваченного токена в поиск заказа) и выдаёт отчёт:

| Взаимодействие | Проверяет |
|----------------|-----------|
| health | `{ ok: boolean }` |
| products | массив `{ id:number, name:string, price:number }` |
| create-order | `{ order_number:string, total:number }` (+ захват токена) |
| get-order | поиск по выданному токену |
| order-privacy | несуществующий токен → 404 (не IDOR) |

Если провайдер не проходит — отчёт указывает **точный путь и тип** расхождения
(напр. отсутствующий `price` или IDOR).

## Запуск

```bash
npm install
export TARGET_URL=http://localhost:8080   # провайдер по умолчанию (роутер/уровень)
npm start                                  # → http://localhost:8095
```

Дашборд: кнопки генерации клиента (JS/Python/TS) с показом кода, поле цели и
верификация против пакта с таблицей взаимодействий.

## API

| Метод | Путь | Назначение |
|-------|------|------------|
| `GET`  | `/api/health` | статус + список языков |
| `GET`  | `/api/spec` / `/api/pact` | спецификация и пакт |
| `GET`  | `/api/codegen?lang=js\|python\|ts-types` | сгенерированный клиент (текст) |
| `POST` | `/api/verify` | `{ target }` → верификация провайдера против пакта |
| `GET`  | `/api/last` | последняя верификация |
| `POST` | `/api/ask` | сводка по верификации/codegen |

## Переменные окружения

| Переменная | По умолчанию | Назначение |
|------------|--------------|------------|
| `TARGET_URL` | `http://localhost:8080` | Провайдер по умолчанию |
| `VERIFY_TIMEOUT_MS` | `5000` | Таймаут запроса |
| `ANTHROPIC_API_KEY` / `ANTHROPIC_MODEL` | — / `claude-opus-4-8` | LLM-сводка |
| `PORT` | `8095` | Порт |

## Тест

```bash
npm test
```

`test/smoke.mjs` проверяет: генерацию JS/Python/TS-клиентов (и что JS-клиент реально
инстанцируется), верификацию **исправного** провайдера (пакт удовлетворён 5/5,
типовой матчер пропускает токен) и **сломанного** (отсутствующий `price` и IDOR
пойманы с точным путём), и HTTP. Без сети и ключа. 15/15.

## Файлы

| Файл | Роль |
|------|------|
| `spec.js` | Машинная спецификация контракта (операции + типы) |
| `codegen.js` | Генерация клиентов (JS / Python / TS-типы) |
| `matcher.js` | Типовые матчеры (структура+типы, не значения) |
| `pact.js` | Consumer-driven contract (взаимодействия + матчеры) |
| `verify.js` | Верификация провайдера против пакта |
| `interpret.js` / `store.js` | Сводка и последняя верификация |
| `server.js` | Express: `/api/codegen`, `/api/verify`, `/api/spec` |
| `public/index.html` | Дашборд codegen + CDC |
| `test/smoke.mjs` | Смоук-тест codegen и верификации |
