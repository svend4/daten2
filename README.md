# A2A settlement — атомарный расчётный слой 💳🌷

Расчётно-клиринговый слой для сделок **агент-агенту**. Рынок агентов (`:8078`) договаривается о цене; **A2A settlement** проводит расчёт по договорённости — **атомарно, с эскроу и сохранением денег**. Отвечает за то, что после «рукопожатия» агентов деньги и обязательства сходятся без частичных состояний.

> Часть системы [flower-shop / 7 уровней](https://github.com/svend4/daten2). Пара к рынку агентов: тот — **переговоры**, этот — **клиринг** договорённости.

## Гарантии

| Свойство | Как обеспечено |
|---|---|
| **Сохранение денег** | двойная запись — каждый перевод балансирован, суммарная масса инвариантна |
| **Атомарность** | saga: плечи исполняются по порядку, при любом сбое — компенсация (всё-или-ничего) |
| **Эскроу** | `reserve` резервирует доступные средства → `capture` (перевод при поставке) / `release` (возврат) |
| **Идемпотентность** | расчёт с тем же `id` применяется ровно один раз (защита от ретраев) |
| **Реверс** | спор/возврат — обратные переводы, только если получатель ещё не распорядился средствами |
| **Без овердрафта** | нельзя зарезервировать/перевести больше доступного (`balance − held`) |

## Как это работает

1. **Двойная запись** (`book.js`) — счета с `balance` и `held`; `available = balance − held`. Перевод `from→to` балансирован → масса денег по всем счетам не меняется никогда.
2. **Эскроу** — `reserve(account, amount)` удерживает доступные средства (не трогая баланс), `capture(holdId, to)` превращает резерв в перевод при подтверждении поставки, `release(holdId)` возвращает резерв.
3. **Saga-клиринг** (`settlement.js`) — расчёт = упорядоченные плечи. Исполняются немедленно (средства промежуточного счёта, напр. эскроу, становятся доступны следующему плечу). Любой сбой или неподтверждённая поставка → компенсация уже исполненного → строго «всё или ничего». Идемпотентность по `id`.
4. **Реверс** — компенсирующие переводы для settled-расчёта; отклоняется без частичного эффекта, если получатель уже потратил средства.
5. **Инварианты** (`invariants.js`) — сохранение массы, отсутствие овердрафта, отсутствие висящих резервов — проверяемы в любой момент.
6. **Два движка**: без ключа — детерминированный клиринг. С `ANTHROPIC_API_KEY` — **LLM-арбитр спора** (`claude-opus-4-8`): uphold / reverse / partial-refund.

## API

| Метод | Путь | Назначение |
|---|---|---|
| POST | `/api/accounts` | `{id, initial}` открыть счёт |
| GET  | `/api/accounts` | счета + масса денег |
| POST | `/api/escrow/reserve` | `{account, amount}` → holdId |
| POST | `/api/escrow/capture` | `{holdId, to}` провести резерв |
| POST | `/api/escrow/release` | `{holdId}` вернуть резерв |
| POST | `/api/settle` | `{id, legs:[{from,to,amount}], deliver?}` атомарный расчёт (идемпотентно) |
| POST | `/api/reverse` | `{settlementId}` реверс |
| GET  | `/api/settlements` | журнал расчётов |
| GET  | `/api/verify-invariants` | проверка инвариантов |
| POST | `/api/ask` | объяснение словами |

## Запуск

```bash
npm install
npm test                 # 19 проверок: инварианты под 500 случайными расчётами + атомарность/идемпотентность/эскроу/реверс + HTTP
node server.js           # :8106, дашборд на /
```

Дашборд (`/`): счета с balance/held/available, статус инвариантов (масса денег сохранена), форма atomic-settle с плечами и флагом поставки, реверс, журнал.

## Переменные окружения

| Переменная | Смысл |
|---|---|
| `PORT` | порт (по умолчанию 8106) |
| `ANTHROPIC_API_KEY` | включает LLM-арбитра споров |

Смоук-тест — property-style: 500 случайных расчётов (часть с нехваткой средств или неподтверждённой поставкой), и после КАЖДОГО проверяются инварианты (масса денег сохранена, овердрафтов нет, висящих резервов нет). Плюс точечно: провал 2-го плеча откатывает весь расчёт, повтор по `id` применяется один раз, эскроу reserve→capture/release, реверс возвращает балансы и отклоняется, если средства уже потрачены.
