# Семантический поиск и рекомендации (AI search)

Поиск букетов **по смыслу, а не по словам**: запрос на естественном языке
(«цветы с приятным запахом, которые долго стоят») кодируется в вектор смысловых
осей, и каталог ранжируется по **косинусной близости**. Товары берутся через тот
же **единый контракт** (`/api/products`), что и витрина с управляющим — поэтому
поиск работает поверх **любого из семи уровней** или роутера.

```
любой уровень (L1…L7) / роутер ─/api/products→ векторный индекс ─cosine→ выдача
```

## Смысловые оси (интерпретируемое пространство эмбеддингов)

Вместо «чёрного ящика» товары и запрос кодируются в фиксированные, читаемые оси —
поэтому у каждого результата видно, **почему** он подошёл:

`аромат · стойкость · романтика · яркость · пышность · бюджет · торжество · нежность`

- **Товар → вектор**: база знаний о цветах (реальные свойства: роза — аромат +
  стойкость + романтика; гвоздика — очень стойкая; пион — пышный и душистый; …)
  **плюс** его описание. Ось «бюджет» вычисляется из реальной цены в каталоге.
- **Запрос → вектор**: те же оси по ключевым словам, а при наличии ключа —
  через Claude (точнее ловит синонимы и перефразировки).

Так «приятный запах + долго стоят» активирует оси *аромат* и *стойкость*, и
сверху оказываются душистые долгостоящие цветы, а не просто совпавшие по буквам.

## Два энкодера запроса, одно пространство

| Энкодер | Когда | Что делает |
|---------|-------|------------|
| **`llm`** (Claude API) | задан `ANTHROPIC_API_KEY` | Claude оценивает запрос по осям (structured output, `claude-opus-4-8`). Anthropic не даёт embeddings-API, поэтому семантику извлекает модель в общее пространство осей |
| **`rules`** | ключа нет | Детерминированный энкодер по ключевым словам осей |

Товары всегда кодируются детерминированно (стабильный индекс); LLM уточняет лишь
вектор запроса. Поиск полностью работает и демонстрируется **без ключа**.

## Запуск

```bash
npm install
export BACKEND_URL=http://localhost:8080   # любой уровень или роутер
# export ANTHROPIC_API_KEY=sk-ant-...        # включить LLM-энкодер запроса
npm start                                    # → http://localhost:8072
```

Откройте `http://localhost:8072` — строка поиска, подсказки-примеры, у каждого
результата шкала релевантности, совпавшие оси и кнопка «похожие →».

## API

| Метод | Путь | Назначение |
|-------|------|------------|
| `GET`  | `/api/health`      | `{ ok, engine, backend, indexed }` |
| `GET`  | `/api/axes`        | список смысловых осей |
| `POST` | `/api/index`       | (пере)индексировать каталог из контракта |
| `POST` | `/api/search`      | `{ query, top }` → `{ axes, results:[{ name, score, matched[] }] }` |
| `GET`  | `/api/similar/:id` | рекомендации: похожие товары по вектору |

## Переменные окружения

| Переменная | По умолчанию | Назначение |
|------------|--------------|------------|
| `BACKEND_URL` | `http://localhost:8080` | Бэкенд единого контракта |
| `ANTHROPIC_API_KEY` / `ANTHROPIC_MODEL` | — / `claude-opus-4-8` | LLM-энкодер запроса |
| `PORT` | `8072` | Порт |

## Тест

```bash
npm test
```

`test/smoke.mjs` индексирует mock-каталог (роза, тюльпан, пион, гвоздика с
описаниями) и проверяет ранжирование по смыслу: «аромат + стойкость» → роза
первой, тюльпан-без-запаха ниже; «недорогое и яркое» → самый дешёвый и яркий
тюльпан; «романтический букет» → роза; «стойкие, не вянут неделями» → гвоздика в
топе; рекомендации «похожие» без самоссылки; фолбэк по названию. Без сети и
ключа. 16/16.

## Файлы

| Файл | Роль |
|------|------|
| `encoder.js` | Смысловые оси, база знаний о цветах, текст→вектор, cosine |
| `index-store.js` | Векторный индекс каталога: поиск и «похожие» |
| `contract.js` | Клиент единого контракта (`/api/products`) |
| `embedder-llm.js` | LLM-энкодер запроса (Claude, structured output) |
| `server.js` | Express: `/api/search`, `/api/similar`, `/api/index`, `/api/axes` |
| `public/index.html` | Поисковый интерфейс |
| `test/smoke.mjs` | Смоук-тест ранжирования и рекомендаций |
