# Chaos-харнесс · устойчивость (Chaos Harness)

Инженерия хаоса для пула уровней: **инъекция сбоев** (падение / задержка / ошибки)
и **автопроверка гипотез SLO** — держится ли доступность за счёт **failover**, когда
уровни ломаются. `failover` из «мы проверили руками» превращается в **непрерывный
воспроизводимый тест**.

```
эксперимент → инъекция сбоя в уровень → нагрузка через устойчивый фронт (failover)
            → метрики (доступность, p95) → проверка гипотезы SLO → восстановление
```

## Инъекция сбоев

Каждый уровень обёрнут инъектором: `down` (503), `latencyMs` (задержка),
`errorRate` (доля 500, **детерминированная** — каждый N-й запрос, для
воспроизводимости). Управляется через API/дашборд — можно «ронять» уровни вживую.

## Устойчивый фронт (SUT)

Именно его SLO проверяется: `resilient` перебирает уровни по порядку и при сбое
**переходит к следующему** (failover). Пока хоть один уровень жив — клиент получает
ответ. Прокси контракта (`/api/products`, …) отдаёт заголовки `X-Served-By` и
`X-Failover`.

## Chaos-эксперименты и гипотезы SLO

Декларативные эксперименты: сбой + гипотеза (`minSuccessRate`, `maxP95Ms`).
«pass» = система повела себя **как ожидалось** — SLO держится при частичном отказе и
ломается только при полном (это доказывает, что харнесс ловит реальные отказы, а не
всегда «зелёный»):

| Эксперимент | Ожидание |
|-------------|----------|
| steady-state | SLO держится |
| one-level-down | failover держит SLO |
| one-level-slow | SLO держится |
| level-errors (500) | failover маскирует ошибки |
| all-down | **нарушение SLO ожидаемо** (полный отказ) |

Весь прогон должен быть «как ожидалось» — иначе харнесс сигналит, что failover не
держит SLO.

## Запуск

```bash
npm install
export CHAOS_TARGETS='[{"id":"level1","name":"PHP","url":"http://localhost:8081"}, …]'
npm start          # → http://localhost:8096
```

Дашборд: карточки уровней с кнопками «уронить / +лаг / ошибки», прогон экспериментов
с таблицей (доступность / p95 / держится ли SLO / итог).

## API

| Метод | Путь | Назначение |
|-------|------|------------|
| `GET`  | `/api/health` / `/api/targets` / `/api/experiments` | статус, уровни, эксперименты |
| `POST` | `/api/faults/:id` · `/api/faults/clear` | инъекция/снятие сбоя |
| `POST` | `/api/run` | прогнать все chaos-эксперименты (проверка SLO) |
| `POST` | `/api/loadtest` | разовая нагрузка через устойчивый фронт |
| `ALL`  | `/api/products`, `/api/orders`, `/api/orders/:id` | устойчивый прокси (failover, заголовки) |
| `POST` | `/api/ask` | сводка по устойчивости |

## Переменные окружения

| Переменная | По умолчанию | Назначение |
|------------|--------------|------------|
| `CHAOS_TARGETS` | локальные L1/2/4 | Пул уровней |
| `CHAOS_TIMEOUT_MS` | `4000` | Таймаут запроса |
| `ANTHROPIC_API_KEY` / `ANTHROPIC_MODEL` | — / `claude-opus-4-8` | LLM-сводка |
| `PORT` | `8096` | Порт |

## Тест

```bash
npm test
```

`test/smoke.mjs` поднимает 3 уровня и проверяет: инъекцию сбоев с **failover**
(A упал/сыпет ошибки → обслужил B), chaos-эксперименты (steady/one-down/errors
держат SLO, all-down нарушает — ожидаемо), снятие сбоев после прогона, живой
устойчивый прокси (`X-Failover`) и метрики нагрузки. Без сети и ключа. 15/15.

| `test/smoke.mjs` | Смоук-тест инъекции, failover и SLO |
