# Полиглот-бенчмарк · перф-артефакт (Polyglot Benchmark)

Воспроизводимое **кросс-языковое перф-исследование**: один и тот же магазин на семи
стеках (PHP → микросервисы) говорит на **едином контракте** и потому сравним «в лоб».
Харнесс нагружает каждый стек, собирает латентность/пропускную способность/надёжность/
эффективность и **генерирует публикуемый отчёт** (Markdown/HTML) — готовый
исследовательский артефакт.

```
7 стеков ─нагрузка(N×C)→ p50/p95/p99 · rps · success · rps/Вт ─→ рейтинг ─→ report.md / report.html
```

## Почему это честное сравнение

Семь стеков — редкий набор, где различается **только реализация**: контракт,
каноническая схема и сид одинаковы. Поэтому разница в латентности/пропускной
способности отражает именно стек (язык/рантайм/хранилище), а не разные API.

## Метрики

| Метрика | Смысл |
|---------|-------|
| `p50/p95/p99` | распределение латентности (мс) |
| `rps` | успешных запросов в секунду |
| `success` | доля 2xx |
| `rps/Вт` | **эффективность** — пропускная способность на ватт номинальной мощности |

Рейтинг: живые вперёд, затем по p95. По умолчанию бьём только по чтению
(`/api/products`) — без побочных эффектов.

## Публикуемый отчёт

`GET /api/report.md` (и `/api/report.html`) — **детерминированный** отчёт (чистая
функция от результатов + параметров): аннотация, **методология**, таблица результатов,
выводы (самый быстрый / самый эффективный / разброс p95), и **раздел
воспроизводимости** с точной командой. HTML самодостаточен (без внешних ссылок).

## Запуск

```bash
npm install
export BENCH_STACKS='[{"id":"level1","name":"L1 · PHP","language":"PHP","storage":"SQLite","watts":12,"url":"http://localhost:8081"}]'
npm start          # → http://localhost:8100
curl -XPOST localhost:8100/api/run -d '{"requests":200,"concurrency":20}'
curl localhost:8100/api/report.md
```

Дашборд: параметры прогона, таблица сравнения стеков, предпросмотр отчёта и кнопки
скачивания `report.md` / `report.html`.

## API

| Метод | Путь | Назначение |
|-------|------|------------|
| `GET`  | `/api/health` / `/api/stacks` | статус и метаданные стеков |
| `POST` | `/api/run` | `{ endpoint, requests, concurrency, warmup }` → результаты + рейтинг |
| `GET`  | `/api/report.md` | публикуемый отчёт (Markdown) |
| `GET`  | `/api/report.html` | отчёт (самодостаточный HTML) |
| `GET`  | `/api/results` | последний прогон (JSON) |
| `POST` | `/api/ask` | сводка (самый быстрый/эффективный) |

## Переменные окружения

| Переменная | По умолчанию | Назначение |
|------------|--------------|------------|
| `BENCH_STACKS` | L1…L7 | Стеки + метаданные (язык/хранилище/watts/url) |
| `ANTHROPIC_API_KEY` / `ANTHROPIC_MODEL` | — / `claude-opus-4-8` | LLM-сводка |
| `PORT` | `8100` | Порт |

## Тест

```bash
npm test
```

`test/smoke.mjs` проверяет: живой прогон по mock-стекам (рейтинг по p95, offline без
ранга, метрика rps/Вт), **детерминированную генерацию отчёта** (та же входная → та же
строка; методология + воспроизводимость + таблица + выводы), самодостаточность HTML,
и HTTP (`/api/run`, `/api/report.md`). Без сети и ключа. 15/15.

## Файлы

| Файл | Роль |
|------|------|
| `stacks.js` | Реестр стеков с метаданными (язык/хранилище/watts) |
| `bench.js` | Нагрузочный замер (перцентили, rps, надёжность) |
| `runner.js` | Прогон по всем стекам + рейтинг + rps/Вт |
| `report.js` | Генератор публикуемого отчёта (Markdown/HTML), чистая функция |
| `interpret.js` / `store.js` | Сводка и последний прогон |
| `server.js` | Express: `/api/run`, `/api/report.md`, `/api/report.html` |
| `public/index.html` | Дашборд + предпросмотр и скачивание отчёта |
| `test/smoke.mjs` | Смоук-тест прогона и генерации отчёта |
