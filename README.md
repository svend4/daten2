# 🌷 daten2 — «магазин цветов» в семи уровнях + AI-слой

Один и тот же магазин цветов, реализованный на **семи возрастающих по сложности
стеках** (от PHP+SQLite до микросервисов), объединённый **единым контрактом** и
надстроенный **слоем ИИ и инфраструктуры**: самооптимизирующийся роутер, разговорная
витрина, ИИ-управляющий, семантический поиск, наблюдаемость, общие сервисы и
MCP-адаптер. `docker-compose.yml` сводит всё в один живой стенд.

> Этот README — **обзор всей системы**. Каждый компонент живёт в своей ветке
> `claude/*` со своим README и smoke-тестом; карта веток — в конце документа.

---

## 💡 Главная идея: контракт как граница

Все семь уровней реализуют один REST-контракт (`openapi.yaml`):

| Метод | Путь | Назначение |
|-------|------|------------|
| `GET`  | `/api/health` | живость + метка уровня |
| `GET`  | `/api/products` | каталог активных товаров |
| `POST` | `/api/orders` | оформить заказ → `order_number` (непубличный токен) + `total` |
| `GET`  | `/api/orders/{order_number}` | статус/состав заказа по токену |

Поскольку граница — **контракт, а не язык**, любой фронтенд, роутер или ИИ-сервис
работает с **любым** уровнем взаимозаменяемо. Это и делает систему «плагинной»:
уровни — сменные бэкенды, а слой сверху пишется **один раз**.

### Каноническая «богатая» схема (два яруса)

Единая схема на всех уровнях (SQL на L1–L5/L7, Prisma на L6), два яруса:

- **Durable (постоянный)** — `categories`, `products`, `customers`, `orders`,
  `order_items`, `order_status_history`.
- **Temporal (временный/кэш, вытесняемый)** — `carts`, `cart_items`,
  `product_view_stats` (на богатых уровнях ложится в Redis-подобный ярус).

## 🤖 Слой над уровнями

Каждый компонент самодостаточен, работает поверх **любого** уровня через контракт и
имеет двойной движок — детерминированное ядро + **опциональный Claude** (LLM
включается при `ANTHROPIC_API_KEY`, иначе всё работает без ключа).

| Компонент | Роль | Порт | Тест | Ветка |
|-----------|------|:----:|:----:|-------|
| **Роутер (ML)** | Выбор уровня по онлайн-модели (латентность/стоимость/нагрузка/надёжность), UCB + failover | 8080 | 12/12 | `claude/ai-router-GBpVR` |
| **Разговорная витрина** | ИИ продаёт покупателю через контракт (диалог → каталог → корзина → заказ) | 8070 | 19/19 | `claude/ai-storefront-GBpVR` |
| **ИИ-управляющий** | Спрос, дозаказ, цены, аномалии — из просадки остатков между снимками | 8071 | 19/19 | `claude/ai-manager-GBpVR` |
| **Семантический поиск** | Поиск по смысловым осям + рекомендации («похожие») | 8072 | 16/16 | `claude/ai-search-GBpVR` |
| **Наблюдаемость** | Бенчмарк 7 стеков (p50/p95/p99, rps, надёжность) + метрики Prometheus | 8074 | 19/19 | `claude/observability-GBpVR` |
| **Цифровой двойник** | Синтетические покупатели генерируют спрос (симуляция, what-if по ценам, живой трафик) | 8075 | 16/16 | `claude/digital-twin-GBpVR` |
| **Файрвол ИИ-агента** | Защита от prompt-injection и злоупотребления инструментами между вводом покупателя и `create_order` | 8076 | 18/18 | `claude/agent-firewall-GBpVR` |
| **Автономный управляющий** | Замкнутая петля наблюдение→анализ→действие с порогом эскалации человеку, kill-switch, аудитом | 8077 | 21/21 | `claude/autonomous-manager-GBpVR` |
| **Капабилити-роутер + общие сервисы** | Статичный роутер по политике + **auth** и **payment** (один раз для всех) | 8081/8091/8092 | 22/22 | `claude/gateway-router-GBpVR` |
| **MCP-сервер** | Адаптер Model Context Protocol — любой ИИ управляет магазином (4 инструмента, stdio) | — | ✓ | `claude/mcp-server-GBpVR` |

> **Роутер (ML)** и **капабилити-роутер** — два поколения одной идеи: первый учится
> на измерениях (self-optimizing), второй маршрутизирует по статичной политике и
> дополнительно проксирует общие `auth`/`payment`. В едином стенде главный вход — ML-роутер.

## 🗺️ Архитектура

```
                    ┌─ витрина :8070 ──┐
   покупатель ─────▶├─ поиск   :8072 ──┤ (через роутер)
                    └─ управляющий :8071┘
                              │
   MCP-клиент (ИИ) ───────────┤
                              ▼
                   ML-роутер :8080  ── /api/health опрос ──▶  L1 L2 L3 L4 L5 [L6] [L7]
                   (UCB + failover)  ── единый контракт ────▶  (лучший уровень, обход упавшего)
                              ▲
   наблюдаемость :8074 ───────┘ (бьёт по уровням напрямую — бенчмарк «в лоб» + /metrics)

   общие сервисы: auth :8091 · payment :8092  (реализованы один раз для всех уровней)
```

## 🚀 Быстрый старт (единый стенд)

```bash
cp .env.example .env        # при желании впишите ANTHROPIC_API_KEY

# базовый стенд: L1–L5 + роутер + витрина + управляющий + поиск + наблюдаемость
docker compose up --build

# добавить L6 (Next.js + PostgreSQL + сид):        docker compose --profile full up --build
# добавить L7 (микросервисы + RabbitMQ + PG):      docker compose --profile enterprise up --build
# добавить общие сервисы auth + payment:           docker compose --profile commerce up --build
# всё сразу:
docker compose --profile full --profile enterprise --profile commerce up --build
```

Каждый сервис собирается **из своей ветки-первоисточника** (git build-context) —
код не дублируется, `docker-compose.yml` и есть единая точка сборки. Для приватного
репозитория укажите доступный `REPO` в `.env`.

### Порты

| URL | Что |
|-----|-----|
| http://localhost:8080 | **ML-роутер** — главный вход (единый контракт) + дашборд трафика |
| http://localhost:8070 | Разговорная витрина |
| http://localhost:8071 | Дашборд ИИ-управляющего |
| http://localhost:8072 | Семантический поиск |
| http://localhost:8074 | Наблюдаемость · бенчмарк 7 стеков (+ `/metrics`) |
| http://localhost:8075 | Цифровой двойник · симуляция спроса и what-if |
| http://localhost:8076 | Файрвол ИИ-агента · песочница атак + защищённое оформление |
| http://localhost:8077 | Автономный управляющий · очередь одобрений + предохранители |
| http://localhost:8081…8087 | Уровни L1…L7 напрямую (для отладки) |
| http://localhost:8091 / 8092 | auth / payment (профиль commerce) |

### Профили

| Профиль | Добавляет |
|---------|-----------|
| *(по умолчанию)* | L1–L5, роутер, витрина, управляющий, поиск, наблюдаемость, двойник, файрвол, автономный управляющий |
| `full` | L6 (`l6-db` PostgreSQL, `l6-seed` разовый сид, `level6`) |
| `enterprise` | L7 (`l7-postgres`, `l7-rabbitmq`, `product-service`, `order-service`, `notification-service`, `level7` nginx) |
| `commerce` | `auth`, `payment` |

Роутер знает про все семь уровней; отсутствующие (профиль не поднят) он видит как
offline и маршрутизирует в остальные — это и демонстрирует его устойчивость.

`ANTHROPIC_API_KEY` необязателен: с ним роутер/витрина/управляющий/поиск/наблюдаемость
включают LLM-движки (Claude, `claude-opus-4-8`); без него — детерминированный режим,
стенд полностью функционален.

## ✅ Проверка

- **Каждый компонент** — собственный smoke-тест (реальный HTTP через границы
  процессов): роутер 12/12, витрина 19/19, управляющий 19/19, поиск 16/16,
  наблюдаемость 19/19, двойник 16/16, файрвол 18/18, автономный управляющий 21/21, контракт (gateway) 22/22, MCP — реальный stdio JSON-RPC.
- **Оркестрация** — живой прогон в контейнерах подтвердил сквозной путь
  **витрина → роутер → живой уровень** (диалоговый заказ приземляется на уровень) и
  **failover на лету** (остановка выбранного уровня → трафик уходит на следующий).
- **Compose** — `docker compose config` валиден для всех профилей (24 сервиса); CI
  проверяет это на каждом пуше.

> Примечание: полная сборка образов **языковых** уровней в песочнице-CI невозможна
> (apt/pip/npm не проходят TLS через самоподписанный прокси) — ограничение среды,
> не стенда. В обычном окружении `docker compose up --build` собирает всё из веток.

## 🎯 Принципы дизайна

1. **Контракт как граница** — не язык. Уровни взаимозаменяемы, слой сверху — один раз.
2. **Двойной движок** — детерминированное ядро + опциональный Claude. Всё работает и без ключа.
3. **Композиция, а не переписывание** — ML-роутер, ИИ, наблюдаемость, auth/payment
   подключаются «переходником» через один и тот же контракт.
4. **Наблюдаемость встроена** — семь стеков сравнимы «в лоб» бенчмарком и метриками.
5. **Каждый кусок самодостаточен** — своя ветка, свой Dockerfile, свой smoke-тест, свой CI.
