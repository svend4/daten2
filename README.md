# Pact для ИИ-агентов 🤝🌷

**Consumer-driven контракт поведения** для агента-продавца. То же, что Pact для REST-микросервисов — но для **поведения LLM-агента**, а не формы JSON. Потребитель (витрина, бизнес) декларирует, *как обязан вести себя* агент; харнесс генеративно верифицирует любую версию модели/движка и **ловит поведенческие регрессии при смене модели**.

> Часть системы [flower-shop / 7 уровней](https://github.com/svend4/daten2). Пакт независим от того, чем реализован агент — детерминированные правила или Claude. Проверяется контракт поведения, а не внутренности.

## Проблема, которую он решает

Вы меняете модель под агентом (обновление, удешевление, смена провайдера). Функциональные тесты «форма ответа» — зелёные. Но новая модель начала **соглашаться на абсурдную скидку 100%** или **оформлять заказ без подтверждения имени**. Это регрессия *поведения*, и обычные тесты её не видят. Пакт — видит.

## Как это работает

1. **Потребитель декларирует ожидания** (`pact.js`) — каждое: категория, набор формулировок ввода, утверждения `mustMatch` / `mustNotMatch`, опционально открытый rubric для LLM-судьи.
2. **Генеративная проверка** (`mutate.js`): каждое ожидание проверяется не на одном примере, а на **семействе эквивалентных формулировок** (регистр, вежливость, пунктуация). Держится — только если проходят все. Детерминированно → воспроизводимо.
3. **Baseline и регрессии** (`runner.compare`): зафиксируйте текущий прогон как baseline. После смены модели новый прогон сравнивается — ожидание, которое **держалось и упало**, помечается регрессией (а исправления — наоборот).
4. **Два движка**: без ключа — детерминированные регулярки. С `ANTHROPIC_API_KEY` дополнительно подключается **LLM-судья** (`claude-opus-4-8`) для открытых критериев, которые нельзя выразить регуляркой.

## Ожидания в пакте (по умолчанию)

| Категория | Ожидание | Суть |
|---|---|---|
| `task` | показывает каталог | на запрос ассортимента называет товары |
| `grounding` | называет цену | не уходит от вопроса о цене |
| `safety` | отказ от абсурда | не соглашается на скидку 100% / нереальный объём |
| `safety` | подтверждение перед заказом | спрашивает имя, не «оформляет» молча |
| `scope` | держится темы | не уходит в анекдоты/погоду |

## API

| Метод | Путь | Назначение |
|---|---|---|
| GET  | `/api/health` | движок (`rules`/`llm`), целевой агент, число ожиданий |
| GET  | `/api/pact` | сам контракт поведения |
| POST | `/api/verify` | `{agentUrl?, path?}` → прогон + сравнение с baseline |
| POST | `/api/baseline` | зафиксировать последний прогон как baseline |
| GET  | `/api/last` | последний прогон |
| POST | `/api/ask` | `{message}` → объяснение регрессий/нарушений словами |

Тестируемый агент должен отвечать на `POST /api/chat` вида `{sessionId, message}` → `{reply}` (путь настраивается через `path` или `AGENT_PATH`).

## Запуск

```bash
npm install
npm test                 # 15 проверок через реальный HTTP: mock-агенты (хороший + регрессировавший)
node server.js           # :8102, дашборд на /
AGENT_URL=http://localhost:8070 node server.js   # цель по умолчанию
```

Дашборд (`/`): кнопка верификации, таблица «держится/нарушено» с провалившей формулировкой и ответом агента, фиксация baseline, баннер регрессии при смене модели.

## Переменные окружения

| Переменная | Смысл |
|---|---|
| `PORT` | порт (по умолчанию 8102) |
| `AGENT_URL` | целевой агент по умолчанию |
| `AGENT_PATH` | путь chat-эндпоинта (по умолчанию `/api/chat`) |
| `ANTHROPIC_API_KEY` | включает LLM-судью для открытых критериев |
| `PACT_TIMEOUT_MS` | таймаут запроса к агенту (8000) |

Смоук-тест поднимает mock-агентов в отдельных сокетах и гоняет весь пакт по HTTP — включая детектор регрессий (хороший агент как baseline, регрессировавший ломает `refuses-absurd`).
