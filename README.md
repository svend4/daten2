# Капабилити-роутер — композиция 7 уровней магазина

Один роутер перед всеми семью реализациями магазина цветов. Благодаря
**единому контракту** (`openapi.yaml` на каждом уровне) он взаимозаменяемо
маршрутизирует запросы на любой живой уровень — «плагинность» без общего кода.

## Как работает
- Опрашивает `/api/health` каждого уровня → знает, кто online и какой это стек.
- Проксирует единый контракт (`/api/products`, `/api/orders`, `/api/orders/<token>`).
- Политика выбора: `?level=N` (явный пин) → `DEFAULT_LEVEL` → самый «способный» из живых.
- Заголовки ответа `X-Served-By-Level` / `X-Served-By-Stack` показывают, кто ответил.

## Запуск
```bash
npm install
# URL уровней задаются через env (иначе localhost:8001..8007)
LEVEL2_URL=https://<flask>.onrender.com DEFAULT_LEVEL=2 npm start
```
Откройте `http://localhost:8080` — дашборд «лестницы возможностей» с живым health,
выбором уровня, загрузкой каталога и оформлением заказа через роутер.

## Служебные эндпоинты
- `GET /gateway/health` — агрегированный статус всех уровней
- `GET /gateway/config` — реестр уровней и политика

## Тест
```bash
npm test   # мок-бэкенд по контракту + проверка агрегации/проксирования
```

## Замечание про состояние
Заказ живёт в БД создавшего уровня, поэтому чтение `/api/orders/<token>`
требует `?level=N` того же уровня. Дашборд делает это автоматически
(запоминает `X-Served-By-Level`).

## Общие сервисы за роутером (реализованы один раз)
Вместо повторения авторизации и оплаты на каждом уровне — два общих сервиса,
на которые роутер проксирует:

- **auth-service** (`services/auth-service`) — `/api/auth/register|login|me|verify`
  (scrypt-хэш паролей, подписанные HMAC-токены). Роутер: `/api/auth/*`.
- **payment-service** (`services/payment-service`) — `/api/payments/intent|confirm|:order`
  (подключаемый провайдер mock/stripe). Роутер: `/api/payments/*`.

Запуск (каждый — свой процесс):
```bash
PORT=8091 node services/auth-service/server.js
PORT=8092 node services/payment-service/server.js
AUTH_URL=http://localhost:8091 PAYMENT_URL=http://localhost:8092 npm start
```
Так авторизация и оплата существуют **один раз для всей системы**, а любой из 7
уровней/фронтендов делегирует им через роутер по единому контракту.

## Consumer-driven contract tests
Один набор проверок доказывает, что бэкенд соответствует единому контракту.
Запускается против ЛЮБОГО уровня или роутера — так один тест доказывает
**взаимозаменяемость всех 7 реализаций**:
```bash
BACKEND_URL=http://localhost:8002 node contract-test/run.mjs   # против уровня
BACKEND_URL=http://localhost:8080 node contract-test/run.mjs   # против роутера
```
Проверено: 22/22 против реальных L1 (PHP) и L2 (Flask) — «один тест, семь реализаций».
Эталонный контракт-совместимый бэкенд: `node contract-test/mock-backend.mjs`.
