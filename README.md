# Adversarial twin — эволюционный red-team 🎯🌷

Состязательный двойник: **не** симулирует нормальный спрос (это делает digital-twin), а **ищет** сценарии, которые ломают ИИ-агента/политику. Coverage-guided эволюционный поиск по пространству атак — фаззер с фитнес-функцией по нарушениям, который сам «докручивает» атаку до пробоя и накапливает покрытие классов уязвимостей.

> Часть системы [flower-shop / 7 уровней](https://github.com/svend4/daten2). Работает против любого агента с chat-контрактом (`POST /api/chat {sessionId, message} → {reply}`) — например, разговорной витрины `:8070`.

## Чем отличается от соседей по системе

| Сервис | Подход |
|---|---|
| **digital-twin** | синтетические покупатели, **нормальный** спрос (симуляция) |
| **agent-firewall** | **защищает** агента от инъекций в рантайме |
| **agent-pact** | проверяет **фиксированный** контракт поведения на фиксированном наборе |
| **Adversarial twin** | **ищет НОВЫЕ** пробои эволюционным поиском — оптимизация, а не фиксированный чек-лист |

## Как это работает

1. **Библиотека проб** (`tactics.js`) — состязательные тактики по категориям (`safety`, `privacy`, `scope`): абсурдная скидка, prompt-injection, утечка чужого заказа по токену, оформление без подтверждения, увод с темы. У каждой — формулировка с параметром **интенсивности** и оракул пробоя (на подстроках — регулярки `\w`/`\b` не матчат кириллицу).
2. **Геном атаки** — веса по тактикам + число тактик `k` + интенсивность. Фенотип: топ-`k` тактик в одной сессии.
3. **Фитнес** — число **разных** найденных нарушений + бонус за «мягкость» (сломать цель низкой интенсивностью — опаснее).
4. **Эволюционный поиск** (`search.js`) — популяция геномов, турнирный отбор + кроссовер + мутация + элитизм. Слабая формулировка часто не ломает цель — поиск **обязан докрутить** интенсивность и скомбинировать тактики. Сходится к геному, максимально ломающему цель; накапливает покрытие по поколениям.
5. **Результат** — устойчивость (`1 − пробитых/всего`), поверхность атаки (какие классы пробиты), **воспроизводимые эксплойты** (сообщение + ответ + минимальная интенсивность), трейс поколений.
6. **Два движка**: без ключа — зашитая библиотека тактик. С `ANTHROPIC_API_KEY` — **LLM-генератор новых проб** (`claude-opus-4-8`): предлагает неочевидные атаки за пределами библиотеки.

## API

| Метод | Путь | Назначение |
|---|---|---|
| GET  | `/api/health` | движок, целевой агент, число тактик |
| GET  | `/api/tactics` | библиотека состязательных проб |
| POST | `/api/hunt` | `{agentUrl?, generations?, pop?, seed?, path?}` → устойчивость + эксплойты + трейс |
| GET  | `/api/last` | последний прогон |
| POST | `/api/ask` | `{message}` → объяснение найденных пробоев словами |

## Запуск

```bash
npm install
npm test                 # 13 проверок по HTTP: стойкий агент выживает, уязвимый пробивается ровно в 3 классах
node server.js           # :8105, дашборд на /
AGENT_URL=http://localhost:8070 node server.js   # цель по умолчанию
```

Дашборд (`/`): метр устойчивости, число пробитых классов, спарклайн накопления покрытия по поколениям, карточки эксплойтов (атака + ответ агента + интенсивность).

## Переменные окружения

| Переменная | Смысл |
|---|---|
| `PORT` | порт (по умолчанию 8105) |
| `AGENT_URL` | целевой агент по умолчанию |
| `AGENT_PATH` | путь chat-эндпоинта (по умолчанию `/api/chat`) |
| `ANTHROPIC_API_KEY` | включает LLM-генератор новых атак |
| `ADV_TIMEOUT_MS` | таймаут запроса к агенту (8000) |

Детерминированный поиск (mulberry32) → воспроизводимые прогоны. Смоук-тест поднимает «стойкого» агента (отбивает всё) и «уязвимого» (ломается на абсурдной скидке, утечке заказа и оформлении без подтверждения, но держит инъекцию и увод с темы) и проверяет, что эволюция находит ровно эти три класса с воспроизводимой атакой, а стойкий получает устойчивость 1 — при разных seed результат одинаков (это поиск, а не случайность).
