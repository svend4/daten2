# Backend-plugin marketplace 🧩🌷

Реестр/маркетплейс **сменных бэкендов-уровней**. Вся система строится на «контракт — граница»: уровни взаимозаменяемы. Маркетплейс формализует supply-side: любой может опубликовать бэкенд-плагин с манифестом; допуск в каталог — только через **живой гейт соответствия контракту**. Роутер забирает `/api/catalog` и авто-регистрирует сертифицированные бэкенды.

> Часть системы [flower-shop / 7 уровней](https://github.com/svend4/daten2). Превращает «7 уровней» в открытую платформу: 8-й, 9-й, N-й бэкенд может прийти извне — если проходит контракт.

## Чем отличается от соседей по системе

| Сервис | Роль |
|---|---|
| **contract-CDC** | верификация уровней против **статичного Pact** |
| **Rosetta** | дифференциальная эквивалентность реализаций |
| **ML/green-роутеры** | **выбор** среди известных бэкендов |
| **Plugin marketplace** | **онбординг** новых бэкендов: манифест → гейт → каталог для роутера |

## Как это работает

1. **Манифест** (`manifest.js`) — `{id (slug), name, version (semver), url, stack, cost?, regions?, capabilities?}`. Валидация формы до любой сети.
2. **Живой гейт соответствия** (`contract.js`) — заявке не верим, проверяем **поведением**: `health` → `products` (непустой, с именем и ценой) → `create-order` (обязателен `order_number` + `total`) → `get-order` (статус + совпадение суммы). Сертификация — только если пройдены все.
3. **Реестр и версии** (`registry.js`) — несколько версий на плагин; **активная** = наивысший сертифицированный не-отозванный semver. `yank` отзывает версию (откат к предыдущей).
4. **Каталог для роутера** — `/api/catalog` отдаёт сертифицированные активные бэкенды в **router-совместимой форме** (`{id, name, url, stack, version, cost, regions}`) → авто-регистрация без ручной правки конфигов.
5. **Два движка**: без ключа — детерминированный гейт. С `ANTHROPIC_API_KEY` — **LLM-ревьюер манифеста** (`claude-opus-4-8`): риск + предложенные теги-возможности.

## API

| Метод | Путь | Назначение |
|---|---|---|
| GET  | `/api/health` | движок + статистика реестра |
| POST | `/api/plugins` | опубликовать плагин (манифест → гейт) → 201 certified / 400 rejected |
| GET  | `/api/plugins` | все плагины и их версии |
| GET  | `/api/plugins/:id` | версии плагина + активная |
| POST | `/api/plugins/:id/yank` | `{version}` отозвать версию |
| GET  | `/api/catalog` | **router-совместимый** список сертифицированных |
| POST | `/api/ask` | объяснение словами (каталог, отклонения) |

## Запуск

```bash
npm install
npm test                 # 14 проверок по HTTP: гейт сертифицирует только настоящий бэкенд + semver + yank + каталог
node server.js           # :8108, дашборд на /
```

Дашборд (`/`): форма публикации манифеста с результатом гейта (какие проверки контракта провалены), реестр с версиями и статусами, кнопки yank, каталог для роутера.

## Переменные окружения

| Переменная | Смысл |
|---|---|
| `PORT` | порт (по умолчанию 8108) |
| `ANTHROPIC_API_KEY` | включает LLM-ревью манифеста |
| `MARKET_TIMEOUT_MS` | таймаут пробы бэкенда (6000) |

Смоук-тест поднимает mock-бэкенды: соответствующий контракту (сертифицируется, score 1.0), ломающий его (заказ без `order_number` → отклонён по соответствию) и недоступный (health провален). Проверяется, что каталог для роутера содержит только сертифицированные, semver выбирает новейшую версию, yank убирает из каталога, а битый манифест отклоняется без обращения к сети.
