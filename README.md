# Shadow / Canary через роутер (Shadow-Canary)

Безопасный выкат новой версии уровня. **Shadow**: клиента всегда обслуживает
`primary`, а копия каждого запроса **зеркалится** на `candidate`, ответы
**диффаются** — клиент этого не видит, риска нет. **Canary**: доля живого трафика
идёт на `candidate` с **авто-откатом** при росте ошибок. Всё поверх **единого
контракта** — кандидатом может быть любая версия любого уровня.

```
        ┌──────────────▶ primary ──▶ ответ клиенту
запрос ─┤   (shadow: копия)               │
        └╌╌╌╌╌╌╌╌╌╌╌╌╌╌▶ candidate ╌╌ diff ┘   (клиент не видит)

canary: доля % → candidate; ошибки кандидата > порога → авто-откат
```

## Shadow · diff-тестирование

Каждый ответ `candidate` сравнивается с `primary` с **нормализацией**: изменчивые
поля (`order_number`, метки времени, токены) **отбрасываются**, чтобы не путать их с
реальными расхождениями. Diff — структурный, по путям (тип/значение/длина/отсутствие
ключа). Копится: сравнено / совпало / расхождений / ошибок кандидата + примеры
diff'ов. **Match-rate** — сигнал готовности к промоушену.

## Canary · процент и авто-откат

Доля `canaryPct` живого трафика уходит на `candidate` (детерминированный сплит),
метрики ошибок считаются по обеим сторонам. Если ошибок кандидата больше порога
(`ROLLBACK_RATE`) при достаточной выборке — **автоматический откат** (`pct→0`,
режим `shadow`) с записью в журнал. `POST /api/promote` продвигает кандидат в
`primary`, когда match-rate высок и ошибок мало.

## Запуск

```bash
npm install
export PRIMARY_URL=http://localhost:8081     # текущая версия уровня
export CANDIDATE_URL=http://localhost:8181    # новая версия-кандидат
export MODE=shadow                            # off | shadow | canary
npm start                                     # → http://localhost:8094
```

Дашборд: primary/candidate/режим/canary%, кнопки «запросы»/«сброс», shadow-метрики
с примерами diff'ов, canary-распределение и здоровье, «промоутить»/«откат».

## API

| Метод | Путь | Назначение |
|-------|------|------------|
| `GET`  | `/api/health` | `{ ok, engine, mode, primary, candidate, canaryPct }` |
| `GET`/`POST` | `/api/config` | конфигурация выката |
| `GET`  | `/api/stats` | shadow-отчёт + canary-здоровье |
| `POST` | `/api/reset` | сбросить статистику |
| `POST` | `/api/promote` · `/api/rollback` | продвинуть кандидат / откатить canary |
| `ALL`  | `/api/products`, `/api/orders`, `/api/orders/:id` | проксирование (заголовок `X-Served-By`) |
| `POST` | `/api/ask` | сводка по выкату |

## Переменные окружения

| Переменная | По умолчанию | Назначение |
|------------|--------------|------------|
| `PRIMARY_URL` / `CANDIDATE_URL` | L1 / — | Текущая и кандидат-версии |
| `MODE` / `CANARY_PCT` | `shadow` / `0` | Режим и доля трафика на кандидат |
| `IGNORE_FIELDS` | `order_number,…` | Изменчивые поля (не расхождение) |
| `ROLLBACK_RATE` / `MIN_SAMPLES` | `0.2` / `5` | Порог авто-отката и минимум выборки |
| `ANTHROPIC_API_KEY` / `ANTHROPIC_MODEL` | — / `claude-opus-4-8` | LLM-объяснение |
| `PORT` | `8094` | Порт |

## Тест

```bash
npm test
```

`test/smoke.mjs` поднимает primary + кандидатов (идентичный/расходящийся/падающий)
и проверяет: клиент всегда получает primary, shadow ловит совпадения и расхождения
(с указанием пути), **игнор изменчивых полей** (`order_number` не считается diff'ом),
изоляцию ошибок кандидата, канареечный сплит (~50%) и **авто-откат** при ошибках.
Без сети и ключа. 11/11.
