# ⬡ NPP-Act — уровень совместимости 4 для Наутилуса

**Наутилус федерирует знание. Это расширение добавляет действие.**

Библиотека экосистемы `svend4` живая, но до сих пор не действующая: протокол
[NPP v1.2](https://github.com/svend4/nautilus/blob/main/PORTAL-PROTOCOL.md)
умеет читать 12 репозиториев и ничего не умеет в них делать. Слова `verb`,
`execute`, `invoke`, `perform`, `consent` не встречаются в его тексте ни разу.

NPP-Act добавляет недостающее измерение, ничего не ломая: уровни 0–3 остаются
как есть, появляется **уровень 4 — Actionable**.

```
Наутилус       — что существует и что с чем совместимо   (каталог)
NPP-Act        — что произойдёт, если это вызвать        (последствие)
n8n / Temporal — как это вызвать и связать в цепочку     (исполнение)
губернатор     — вправе ли агент это вызывать            (удержание)
```

---

## Главная идея: схема последствий, а не схема вызова

OpenAPI, gRPC и GraphQL описывают **форму** вызова. Этого хватает программисту
и не хватает автономному агенту. Чтобы решить, **вправе ли он это сделать**,
агенту нужны четыре вещи, которых нет ни в одной из этих схем:

| Вопрос агента | Поле |
|---|---|
| Что это изменит в мире? | `effect`: read · reserve · commit · money · destroy |
| Можно ли это отменить? | `reversible` / `reverse` |
| Сколько это стоит и чьих денег? | `cost` |
| Нужен ли здесь человек? | `consent`: none · notify · confirm · two_party |

## Запуск

Зависимостей нет — только стандартная библиотека Python 3.11+.
API-ключи не нужны нигде, всё работает офлайн.

```bash
# все наборы проверок
for t in test_act test_gateway test_profile test_router test_n8n \
         test_freelance test_market test_calendar; do python3 -m act.tests.$t; done

# сквозной сценарий: клиника (время) + магазин цветов (товар)
python3 -m act.demo.scenario

# сравнение семи уровней по профилям возможностей
python3 -m act.npp_act.profile

# шлюз рантайма — единственная дверь для оркестратора
python3 -m act.gateway --port 8200 --budget 300 --owner person:anna

# сервисы
python3 -m act.services.venue.server     --port 8210 --reset   # продаёт ВРЕМЯ
python3 -m act.services.freelance.server --port 8220 --reset   # продаёт КОМПЕТЕНЦИЮ
```

## Три природы ресурса

Сервисы выбраны нарочно: они показывают, что протокол не заточен под торговлю.

| Ресурс | Пример | Возвратность | Схема глаголов |
|---|---|---|---|
| **Товар** | букет | возвратен: непроданный продашь завтра | сразу `commit` |
| **Время** | приём у врача | **невозвратно**: непроданный вторник не продашь никогда | `reserve` → `commit` |
| **Компетенция** | работа фрилансера | обязательство во времени с приёмкой | бриф → оценка → контракт → сдача → приёмка |

Невозвратность времени и есть то, что отличает ERP сферы услуг от товарного.
Отсюда правило проектирования:
**любой многошаговый сценарий начинается с обратимых шагов.**

## Двустороннее обязательство

То, ради чего расширение существует: действие, в котором участвуют два
независимых профиля, и оба несут предъявляемую ответственность.

```
offer → hold → accept → commit
```

Запись `commitment` ложится в **оба** журнала с общим идентификатором и хэшами
записей обеих сторон. Ни одна сторона не может изменить свою запись, не
разорвав собственную цепь. Проверяющий, имея оба журнала, убеждается, что обе
стороны записали одно и то же.

Если согласие не наступило до истечения удержания, инициатор **обязан**
отпустить ресурс. В демонстрации это видно в журнале: эскалация на шаге брони
→ автоматический `slot.release` → слот снова свободен.

## Профили уровней: дефекты аудита как часть манифеста

Семь уровней daten2 реализуют один контракт, но держат его неодинаково.
Раньше это знание жило в отчёте аудита; теперь оно машиночитаемо.

```
L1 level1-php        minimal  sqlite   22/22  tx=да   склад=нет  конкур=да
L2 level2-flask      light    sqlite   22/22  tx=да   склад=нет  конкур=да
L3 level3-django     medium   sqlite   22/22  tx=нет  склад=нет  конкур=да
L4 level4-express    light    sqlite   22/22  tx=да   склад=нет  конкур=нет
L5 level5-react-flask medium  sqlite   22/22  tx=да   склад=нет  конкур=да
L6 level6-nextjs     heavy    postgres  7/22  tx=да   склад=да   конкур=да
L7 level7-enterprise heavy    postgres 15/22  tx=да   склад=нет  конкур=да
```

Уровень, который не умеет конкурентные заказы, **обязан это объявить**.
Парсер следит за непротиворечивостью: объявленный дефект при
`concurrency_safe: true` отвергается как реклама. У каждого дефекта есть
`evidence` — указание на место в коде, по которому утверждение перепроверяется.

Тест `test_profile.py` читает **настоящие исходники уровней** с аудируемых
веток и падает, если манифест расходится с кодом. Эта сверка уже исправила два
факта аудита: проверку остатка делает только L6 (остальные шесть выбирают
`SELECT name, price` и затем `UPDATE stock = stock - ?` без сравнения), а L3 не
транзакционен — `api_create_order` идёт без `transaction.atomic`.

### Роутер выбирает по требованию

```
Требование: надёжный приём заказов под нагрузкой
Подходят: L1, L2, L3, L5
Отклонены:
  · level4-express: не выдерживает параллельные заказы
  · level6-nextjs: соответствие контракту 7/22, требуется полное
  · level7-enterprise: соответствие контракту 15/22, требуется полное
```

Роутер **не подменяет молча** уровень, не удовлетворяющий требованию: если
подходящих нет, это отказ с объяснением. Тихая подмена — ровно тот класс
ошибок, ради которого существует слой удержания.

## Что проверено

**1452 проверки в 19 наборах**, все по реальному HTTP между процессами:

| Набор | Проверок | Что доказывает |
|---|---:|---|
| `test_act` | 41 | ядро: манифест, журнал, гейт, двустороннее обязательство |
| `test_gateway` | 23 | гейт не обойти; dry_run действительно сухой |
| `test_profile` | 79 | профили сверены с настоящими исходниками уровней |
| `test_router` | 89 | выбор по требованию, объяснимый отказ |
| `test_n8n` | 64 | каталог и узел корректны |
| `test_freelance` | 95 | полный цикл услуги, ёмкость, эскроу, доработка |
| `test_market` | 105 | масса денег сохраняется, saga откатывается |
| `test_calendar` | 60 | конфликты расписания обнаруживаются |

Сервисы здесь **не проверяются против собственных моков** — это сознательно.
Аудит экосистемы показал, что самосертификация и есть главный способ обмануть
себя: `plugin-marketplace` имеет 14/14 зелёных тестов и при этом отвергает все
настоящие бэкенды, потому что его мок не валидирует то, что валидирует контракт.
