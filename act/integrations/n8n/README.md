# ⬡ NPP-Act × n8n

**n8n исполняет. Губернатор удерживает. Это разные слои, и второй не отменяется первым.**

Четыре слоя, которые нельзя смешивать (SPEC-NPP-ACT.md §9):

| Слой | Чем является | Кто |
|---|---|---|
| Каталог | что существует и что с чем совместимо | **Наутилус** |
| Последствие | что произойдёт, если это вызвать | **NPP-Act** (манифест) |
| Исполнение | как это вызвать и связать в цепочку | **n8n** |
| Удержание | вправе ли агент это вызывать | **губернатор + журнал** |

Подключение к n8n не делает слой удержания необязательным. Наоборот: оркестратор —
это и есть та машина, которая начинает вызывать глаголы без человека в контуре,
и именно поэтому гейт должен стоять **не в workflow**, а в рантайме.

---

## Главное предупреждение: узел не является границей безопасности

Узел `NppAct` — поле ввода в редакторе. Любой, кто может править workflow, может
снять в нём галочку «сухой прогон». Поэтому:

* узел **не умеет вызывать сервисы** — он физически не может сделать
  `POST /api/bookings` магазина или клиники; единственное, что он читает у сервиса
  напрямую, — его манифест (`GET /.well-known/npp-act.json`), то есть объявление,
  а не действие;
* единственный адрес, который он знает, — рантайм NPP-Act (`POST /act/perform`);
* решение принимает губернатор в рантайме, запись делает журнал там же;
* перед настоящим действием узел проверяет, что по указанному адресу действительно
  рантайм (`GET /api/health` → `runtime: "npp-act"`), а не сам сервис. Это ловит
  самую частую ошибку конфигурации — «подставлю адрес сервиса, так короче».

Что из этого следует: workflow можно читать как заявление о намерениях, но
доказательством допустимости действия является журнал рантайма, а не схема в n8n.

## Быстрый старт

```bash
# 1. Рантайм NPP-Act: губернатор, журнал, бюджет. Единственная дверь действия.
python3 -m act.gateway --port 8200 --budget 300 --owner person:anna \
    --ledger /var/lib/npp/anna.jsonl

# 2. Каталог последствий — посмотреть глазами
python3 -m act.integrations.n8n.export_catalog --format table

# 3. Каталог для n8n — файлом
python3 -m act.integrations.n8n.export_catalog --format json --out /tmp/npp-act-catalog.json

# 4. Узел в n8n: пакет копируется (или линкуется) в каталог пользовательских узлов
mkdir -p ~/.n8n/custom && ln -s "$PWD/act/integrations/n8n" ~/.n8n/custom/n8n-nodes-npp-act
# либо: N8N_CUSTOM_EXTENSIONS=/путь/к/act/integrations/n8n n8n start
```

Зависимостей нет: `dependencies` пуст, `n8n-workflow` объявлен как
необязательный peer (он уже есть в рантайме n8n). API-ключи не нужны нигде.

Экспортёр запускается и модулем (`-m act.integrations.n8n.export_catalog`), и файлом
по пути — он сам находит корень репозитория.

### Ключи экспортёра

| Ключ | Значение |
|---|---|
| `--format json\|table` | машине или человеку |
| `--out FILE` | записать в файл; на stdout остаётся отчёт |
| `--manifests DIR` | каталог `*.act.json` (по умолчанию `act/manifests`) |
| `--no-levels` | не подхватывать `manifests/levels` (семь уровней daten2) |
| `--service S`, `--effect E` | фильтры, можно повторять |
| `--gateway URL` | адрес рантайма, который попадёт в каталог |

Битый манифест — это отказ с кодом `2`, а не каталог без одного сервиса:
половина объявленных последствий опаснее их отсутствия.

## Контракт рантайм-шлюза

Шлюз живёт отдельно от узла (эталонная реализация — `act/gateway.py`). Узел
полагается ровно на этот контракт и ни на что больше.

### `POST /act/perform`

```json
{
  "service": "venue-clinic-nord",
  "verb": "booking.create",
  "payload": { "hold_id": "h_7f3a…", "name": "Анна Иванова", "max_money": 90 },
  "idempotency_key": "bk-1",
  "dry_run": true,
  "hold": { "hold_id": "h_7f3a…", "expires_at": "2026-10-09T12:02:00Z" }
}
```

Ответ — всегда `200`, если запрос разобран. **Отказ губернатора не является
ошибкой транспорта:** workflow должен уметь ветвиться по `verdict`, а не ловить
исключение.

```json
{
  "dry_run": false,
  "decision": { "verdict": "admit|block|escalate", "reason": "…",
                "alternative": { "verb": "slot.hold" }, "checks": ["…"] },
  "executed": true,
  "budget_remaining": 255.0,
  "result": { "ok": true, "status": 201, "body": { "booking_number": "…" } }
}
```

| Код | Когда |
|---|---|
| `200` | решение принято (в том числе `block`/`escalate`) |
| `400` | нет `service` или `verb` |
| `502` | допущено, но сервис недоступен |
| `404` | маршрута нет — в частности, нет и не будет эндпоинта «выполнить произвольный HTTP-запрос» |

При `dry_run: true` шлюз **обязан** только спросить губернатора: ни вызова
сервиса, ни записи в журнал. Тест это проверяет по длине журнала, а не по словам.

### Остальные эндпоинты

| Метод | Путь | Значение |
|---|---|---|
| `GET` | `/api/health` | живость + маркер `runtime: "npp-act"` |
| `GET` | `/act/catalog` | плоский каталог — его читают выпадающие списки узла |
| `GET` | `/act/services` | сервисы, профили, адреса, Q6 |
| `POST` | `/act/confirm` | зафиксировать согласие на `service:verb:key` |
| `GET` | `/act/ledger`, `/act/ledger/verify` | записи и целостность хэш-цепи |
| `GET` | `/act/budget` | остаток бюджета профиля |

## Поля узла

| Поле | Тип | По умолчанию | Смысл |
|---|---|---|---|
| `operation` | options | `perform` | выполнить глагол · прочитать каталог |
| `gatewayUrl` | string | `http://127.0.0.1:8200` | корень рантайма (не сервиса) |
| `catalogSource` | options | `gateway` | реестр рантайма · манифест сервиса |
| `manifestUrl` | string | — | `/.well-known/npp-act.json` |
| `service` / `verb` | options | — | подгружаются из каталога; глагол подписан эффектом |
| `payload` | json | `{}` | по схеме `input` из манифеста |
| `idempotencyKey` | string | — | обязателен для `commit`/`money` |
| `hold` | json | `{}` | `{hold_id, expires_at}` парного `reserve` |
| `dryRun` | boolean | **true** | только решение губернатора, без исполнения |
| `preflight` | boolean | true | сначала спросить, при отказе не отправлять настоящий запрос |
| `verifyGateway` | boolean | true | проверить `runtime: "npp-act"` |
| `failOnBlock` | boolean | false | отказ как ошибка узла вместо выходного элемента |
| `timeoutMs` | number | 30000 | таймаут запроса к рантайму |

Выход узла плоский, и `verdict` вынесен наверх намеренно: главное, что узел
сообщает миру, — не «данные», а **было ли это вправе случиться**.

```json
{ "service": "…", "verb": "…", "dry_run": false, "verdict": "block",
  "reason": "обязательство без ключа идемпотентности", "alternative": null,
  "checks": ["…"], "executed": false, "stopped_by": "preflight",
  "budget_remaining": 300.0, "result": null, "status": null, "ok": null }
```

### Почему `dryRun` включён по умолчанию

В редакторе дешевле узнать последствие, чем его получить. Узел, который при
первом перетаскивании мышью способен оформить заказ, — плохой узел.

### Почему `preflight` — удобство, а не гарантия

`preflight` экономит отказ: сначала сухой прогон, и при `block`/`escalate`
настоящий запрос не отправляется вовсе. Но если его выключить, губернатора всё
равно спросят — в рантайме, на том же `POST /act/perform`. Разница только в том,
попадёт ли отказ в журнал.

### Чего узел не умеет умышленно

* **Произвольного HTTP-вызова.** Нет такого поля и не будет: оно отменяет манифест.
* **`POST /act/confirm`.** Согласие (`confirm`, `two_party`) даёт человек или
  встречный профиль — не workflow от их имени. Workflow, подтверждающий сам себе,
  это `consent: none` с лишними шагами. Для ожидания согласия в n8n есть `Wait`
  и формы; подтверждение приходит в рантайм отдельным путём.
* **Хранения ключей.** `credentials` пуст: рантайм слушает на localhost и
  принадлежит владельцу профиля.

## Пример цепочки

```
Schedule ──▶ NppAct: venue-clinic-nord / slot.list      (read,    dryRun=false)
         ──▶ NppAct: venue-clinic-nord / slot.hold      (reserve, dryRun=false)   ← обратимо
         ──▶ NppAct: venue-clinic-nord / booking.create (commit,  dryRun=true)    ← показать человеку
         ──▶ Wait / человек подтверждает → POST /act/confirm
         ──▶ NppAct: venue-clinic-nord / booking.create (commit,  dryRun=false)
         ──▶ IF verdict ≠ admit ──▶ NppAct: slot.release                          ← убрать за собой
```

Порядок не случайный: правило проектирования NPP-Act — **любой многошаговый
сценарий начинается с обратимых шагов**, а несостоявшаяся сделка обязана
отпустить удержание, иначе ресурс залипает.

## Что проверено

```bash
python3 -m act.tests.test_n8n     # 64 проверки
```

Моков модуля под собственные допущения здесь нет. Каталог проверяется по
**настоящим** манифестам `act/manifests` (сверка с `Registry`, а не с константой
в тесте), а узел запускается **настоящим** `node` и ходит по сети в **настоящий**
`python3 -m act.gateway`, за которым стоят настоящие сервисы заведения и цеха.
Мокается только сам n8n — хост, которого в репозитории нет.

Проверяется, в частности:

- у каждого глагола-обязательства объявлены и `consent`, и способ идемпотентности;
- каталог не отдаёт `base_url` сервиса как адрес действия;
- поля в `NppAct.node.js` и `NppAct.node.json` совпадают **точно** (два артефакта
  сверяются друг с другом, а не каждый сам с собой);
- сухой прогон не меняет склад времени у сервиса и **не оставляет записей в журнале**;
- настоящее чтение проходит через рантайм и попадает в журнал всеми четырьмя стадиями;
- обязательство без ключа идемпотентности отклонено губернатором, а не узлом;
- `preflight` действительно не отправляет настоящий запрос (проверяется длиной журнала);
- указание адреса **сервиса** вместо адреса рантайма — отказ узла работать;
- после всех попыток хэш-цепь журнала цела.

Известное ограничение, зафиксированное тестом: сервис заведения отдаёт
`/.well-known/npp-act.json` кодом 404 (путь к файлу манифеста вычисляется на один
уровень выше нужного), поэтому чтение манифеста напрямую у сервиса проверяется на
цехе, где тот же путь работает. Это дефект сервиса, не узла.
