# ⬡ NPP-Act × Nautilus — пакет для переноса

**Наутилус умеет федерировать знание. Этот пакет учит его федерировать действие —
не меняя ни одной строки в уровнях 0–3.**

Прав на запись в `svend4/nautilus` нет, поэтому здесь лежит готовый пакет:
владельцу остаётся скопировать два файла и вставить восемь строк. Пошагово —
в [`APPLY.md`](APPLY.md), десять минут.

| Файл | Куда едет | Роль |
|---|---|---|
| `npp_act_adapter.py` | `nautilus/adapters/npp_act.py` | адаптер: глагол → `PortalEntry` |
| `passport-daten2.md` | `nautilus/passports/npp_act.md` | паспорт уровня 4 + мосты |
| `registry-entry.json` | строки в `nautilus/nautilus.json` | запись реестра |
| `APPLY.md` | — | инструкция владельцу |
| `../../tests/test_nautilus_adapter.py` | — | 192 проверки против настоящего протокола |

## Задача, которую пришлось решить

Единственная структура, пересекающая границу адаптера в Наутилусе, — это
`PortalEntry`. У неё есть поле `format_type`, и все семь его допустимых
значений v1.2 описывают то, что можно **прочитать**:

```
document · concept · rule · theory · schema · archetype · conversation
```

Глагол `order.create` не является ни одним из них. Он не документ и не концепт:
он **создаёт обязательство в мире**. Поэтому первый же вопрос переноса — какой
`type` ставить записи о действии.

### Решение: новый тип `action` + честная деградация к `document`

Протокол сам оставил эту дверь открытой — §4.1:

> Implementations MAY define additional values. Unknown values MUST be
> treated as `document` by consuming code.

То есть новый тип не нарушение, а предусмотренный путь расширения. Выбран
минимальный вариант: **одно новое значение** `action`, никаких новых полей в
`PortalEntry`, всё остальное уезжает в свободный `metadata`.

Почему нельзя просто поставить `document` и не изобретать тип:

> читатель, который видит `document`, вправе считать запись безопасной для
> показа, пересказа и индексации. Запись о глаголе `money` безопасной не
> является. Соврать типом — значит снять с читателя различение риска, которое
> и есть единственный смысл этого расширения.

Почему нельзя поставить `action` и не думать о старых читателях: читатели
старше v1.2 требование о деградации не исполняют и могут упасть или потерять
запись. Поэтому у адаптера есть явный режим:

```python
NppActAdapter(degrade=True)   # format_type = "document"
                              # metadata["format_type"] = "action"
```

**Деградация обязана быть восстановимой.** Если бы при `degrade=True` правда
о типе исчезала, это была бы не деградация, а подмена: читатель получил бы
`document` и никакого способа узнать, что перед ним необратимый перевод денег.
Поэтому настоящий тип всегда остаётся в `metadata`.

Запись о манифесте сервиса получает существующий тип `schema` — и это не
компромисс, а точность: манифест действительно схема, только не данных, а
последствий.

### Сводка типов, которые отдаёт адаптер

| Запись | `format_type` | Сколько |
|---|---|---|
| якорь расширения (`npp_act:spec`) | `schema` | 1 |
| манифест сервиса (`npp_act:<service>`) | `schema` | по числу сервисов |
| глагол (`npp_act:<service>.<verb>`) | **`action`** → `document` при деградации | по числу глаголов |

На настоящих манифестах `act/manifests/` (10 файлов) это 1 + 10 + 56 = **67 записей**.

## Q6-адрес глагола: шесть бит последствия

Уровень 2 требует координату Q6, и уровень 4 её наследует (SPEC §8: «SHOULD
также удовлетворять уровню 2, чтобы его глаголы были findable наравне со
знанием»). Вопрос — что кладётся в биты.

Для знания в Наутилусе биты означают класс CA и уровень абстракции (§9.2).
Для действия это бессмысленно. У действия есть свои три оси — ровно те, по
которым агент решает, вправе ли он это сделать (SPEC §1):

```
b5 b4 b3   эффект: что изменится в мире  (3 бита, монотонно по тяжести)
           000 read     ничего не меняет
           001 reserve  удерживает ресурс временно, истекает сам
           010 commit   создаёт обязательство
           011 money    двигает деньги
           100 destroy  уничтожает состояние необратимо
           101 110 111  зарезервировано под будущие эффекты

b2         необратимость: можно ли это отменить
           0 обратим (объявлен reverse)
           1 необратим

b1 b0      согласие: нужен ли здесь человек
           00 none       агент действует сам
           01 notify     действует и уведомляет постфактум
           10 confirm    нужно подтверждение владельца до исполнения
           11 two_party  нужно согласие обоих профилей
```

**Почему «необратимость», а не «обратимость».** Чтобы единица всегда означала
«тяжелее». Тогда число единиц в адресе растёт вместе с риском, и адрес можно
читать глазами: `000000` — безобидное обратимое чтение, `111111` — предел.

**Почему эффект занимает старшие биты.** Старшие биты определяют порядок
сортировки по числовому значению адреса: `sorted(entries, key=q6)` сам ставит
деньги выше чтения. Это нужно каждый раз, когда выдачу показывают человеку.

Проверка на настоящих манифестах:

| Адрес | Глагол | Чтение |
|---|---|---|
| `000100` | `flower-shop.catalog.list` | read · необратим · без согласия |
| `001000` | `freelance-guild.quote.request` | reserve · обратим · без согласия |
| `010011` | `freelance-guild.contract.sign` | commit · обратим · согласие обоих |
| `010110` | `flower-shop.order.create` | commit · необратим · подтверждение |
| `011110` | `freelance-guild.payment.release` | money · необратим · подтверждение |
| `111111` | `npp_act:spec` | зарезервированная тяжесть · необратимо · оба |

Отображение **детерминированное**: тот же глагол даёт тот же адрес на любой
машине, никакой курации. Обратная функция `decode_q6()` возвращает последствие
из адреса — без неё окрестность Хэмминга (`portal.query_neighbors`) показывала
бы человеку шесть бит без объяснения.

Из 64 вершин глаголу доступны **40** (5 эффектов × 2 обратимости × 4 согласия);
24 вершины с `severity ≥ 101` зарезервированы и настоящим глаголом не
занимаются никогда. Адрес `111111` у якоря расширения выбран намеренно: это
точка, которой не может достичь ни один глагол, — «последствие неизвестной
тяжести, необратимое, требующее согласия обоих». Предел, ради охраны которого
расширение и написано.

### Две оговорки, без которых схема врёт

**Биты `b5..b3` — двоичное число, а не код Грея.** Расстояние Хэмминга внутри
этого поля нельзя читать как семантическую близость: `001` (reserve) и `011`
(money) отличаются одним битом, но двумя шагами тяжести. Для упорядочивания по
риску надо брать `severity`; соседство по Хэммингу означает только «тот же
профиль последствия с точностью до одной оси». Код Грея решил бы это, но ценой
потери монотонности числового значения — а сортировка по риску нужнее, чем
красивое соседство.

**Это другая проекция, чем в §9.2.** NPP-Act занимает то же 64-вершинное
пространство, но кладёт в него другую сущность. §9.3 это прямо разрешает
(«Each adapter defines a rule mapping its native entities to Q6»). Совпадение
адреса глагола с адресом концепта — **коллизия по §9.4, а не тождество**.
Из равенства адресов нельзя выводить равенство смыслов; `detect_conflicts`
из `bridge_registry.py` увидит такие пары и имеет право пометить их как
расхождение — это ожидаемое поведение, а не ошибка.

## Чего адаптер не умеет — и не должен

Адаптер **не вызывает ни один глагол**. Единственный сетевой запрос, который он
делает, — `GET {base_url}/.well-known/npp-act.json`, то есть чтение
**объявления**, а не действия. Он не знает адреса шлюза и не содержит кода
исполнения.

Разделение слоёв то же, что в интеграции с n8n (SPEC §9):

| Слой | Чем является | Кто |
|---|---|---|
| Каталог | что существует и что с чем совместимо | **Наутилус** ← этот адаптер |
| Последствие | что произойдёт, если это вызвать | **NPP-Act** (манифест) |
| Исполнение | как это вызвать | рантайм `act/gateway.py` |
| Удержание | вправе ли агент это вызывать | губернатор + журнал |

Каталог, в котором видно действие, — это не пульт. Если когда-нибудь в
`index.html` Наутилуса появится кнопка «выполнить», она обязана идти в
`POST /act/perform` шлюза, где стоит гейт, а не в сервис напрямую.

## Источники данных: живое, потом файл, потом статика

Уровень 4 обязывает к живому контуру, но после переноса адаптер окажется в
репозитории Наутилуса, где каталога `act/manifests` нет. Поэтому порядок:

| № | Источник | Признак в `metadata` |
|---|---|---|
| 1 | явно переданные пути и URL | `source_kind: "file" / "http"` |
| 2 | `NPP_ACT_MANIFESTS` (пути через `os.pathsep`) | `"file"` |
| 3 | найденный рядом `act/manifests` | `"file"` |
| 4 | вкомпилированный минимум | `"static"`, `is_fallback=True` |

Если один и тот же сервис пришёл и файлом, и по сети, **побеждает живой**: по
сети сервис заявляет, что умеет СЕЙЧАС, а файл в репозитории мог отстать.

Четвёртый пункт — требование §4.4: адаптер MUST вернуть непустой список и
MUST NOT бросить исключение. Статические записи помечены `is_fallback=True`,
и релевантность у них по §5.1 вдвое ниже — соврать «действий нет» нельзя, но и
выдать статику за живое тоже.

```python
# каталог из файлов репозитория, без сети
NppActAdapter(["act/manifests"], live=False)

# живой сервис: читается манифест работающего цеха
NppActAdapter(["http://127.0.0.1:8220"])

# всё сразу; дубликат сервиса разрешается в пользу живого
NppActAdapter(["act/manifests", "http://127.0.0.1:8220"])
```

## Почему файл один и без зависимостей

Адаптер самодостаточен: ни `act.npp_act`, ни внешних пакетов. Это сознательно —
перенос не должен требовать от владельца Наутилуса установить daten2.

Следствие: в адаптере живёт **свой, терпимый читатель манифеста**. Это не
валидатор NPP-Act (полный валидатор — `act/npp_act/manifest.py`, он остаётся на
стороне сервиса). Читатель берёт то, что нужно записи каталога, и молча
пропускает глагол без обязательного поля: адаптер в портале обязан не падать,
а неполный манифест — ошибка сервиса, а не повод уронить чужой каталог.

Две защиты от расхождения этих двух чтений — в тесте:

1. каждое поле, прочитанное адаптером, сверяется с результатом **настоящего**
   `act.npp_act.load_manifest` на всех 10 манифестах;
2. неизвестный `consent` трактуется в сторону человека (`confirm`), а не в
   сторону `none` — ошибка в манифесте не должна открывать агенту дорогу.

Импорт базового протокола — три попытки по убыванию «настоящести»:
`from .base` (внутри `nautilus/adapters/`) → `from adapters.base` (Наутилус в
`sys.path`) → локальные определения-дублёры (daten2 без Наутилуса). Тест
подкладывает **настоящий** `adapters/base.py` из клона и проверяет, что
`NppActAdapter` — подкласс настоящего `BaseAdapter`, а записи — экземпляры
настоящего `PortalEntry`. Дублёр сверяется с исходником по полям: разойдутся —
тест упадёт.

## Запуск

```bash
# что отдаст портал на пустой запрос
python3 -c "
from act.integrations.nautilus.npp_act_adapter import NppActAdapter
a = NppActAdapter(['act/manifests'], live=False)
for e in a.fetch(''):
    print(e.metadata['q6'], e.format_type.ljust(8), e.id)
"

# поиск по адресу последствия: деньги, необратимо, нужно подтверждение
python3 -c "
from act.integrations.nautilus.npp_act_adapter import NppActAdapter, decode_q6
print(decode_q6('011110'))
print([e.id for e in NppActAdapter(['act/manifests'], live=False).fetch('011110')])
"

# тест (клон svend4/nautilus нужен: без него проверять нечем)
python3 -m act.tests.test_nautilus_adapter
```

Тест ищет клон Наутилуса по `NAUTILUS_SRC`, затем в `~/svend4/nautilus`,
`../nautilus` и рядом. Если клона нет, тест отказывается работать, а не
«проходит на дублёре»: сверка адаптера с собственным дублёром была бы ровно той
самосертификацией, из-за которой `plugin-marketplace` в этом же репозитории
имеет 14/14 зелёных и отвергает все настоящие бэкенды.

Десять групп проверок, и ни одна не сверяет модуль с моком:

| № | Группа | Против чего проверяется |
|---|---|---|
| 1 | протокол | настоящий `adapters/base.py` + требования из текста `PORTAL-PROTOCOL.md` |
| 2 | записи | настоящие `act/manifests/**` (10 файлов, 56 глаголов) |
| 3 | поля записей | настоящий валидатор `act.npp_act.load_manifest` — все 56 глаголов |
| 4 | Q6 | 40 комбинаций последствия, круговой обход `decode(encode(x))` |
| 5 | запись реестра | настоящий `nautilus.json` + шаблон `repo` из настоящей схемы |
| 6 | паспорт | настоящие `passport_schema.json`, `bridge_registry.py`, `health_check.py`, §15.2 |
| 7 | живой контур | настоящий сервис цеха по сети + настоящий 404 на несуществующий манифест |
| 8 | устойчивость | минимальный манифест (валидность подтверждает настоящий валидатор), битый JSON, мусор в запросах |
| 9 | инструкция | каждая строка, которую `APPLY.md` велит найти, существует в целевом файле |
| 10 | **приёмка** | шаги 1–7 применены к КОПИИ настоящего клона, после чего в ней запущены настоящие `portal.py`, `bridge_registry.py`, `health_check.py`, `generate_passport.py` |

Группа 10 отвечает на единственный вопрос, который здесь имеет значение —
**примет ли**. Оригинал клона не трогается; все правки идут в копию во
временном каталоге, по тем же якорным строкам, которые названы в `APPLY.md`.
Если бы инструкция врала хоть в одном шаге, патч не нашёл бы якорь либо портал
не поднялся.

### Что группа 10 нашла и что из этого следует

`portal.query_neighbors(bits, k)` опрашивает адаптеры через `fetch("")` — то
есть видит не весь каталог, а представительную выборку. Первая версия выборки
схлопывала адрес до одного представителя, и второй претендент на тот же адрес
(`payment.release` рядом с `escrow.refund` на `011110`) становился **не
находимым окрестностным поиском портала**. Это не косметика, а потеря записи,
и нашлась она только потому, что тест запускает настоящий портал.

Поэтому выборка теперь добирает остаток мест коллизиями по §9.4: каждый адрес
представлен, а свободные места отданы спорящим за тот же адрес. Полный ответ по
адресу всегда даёт `fetch("<шесть бит>")` — он возвращает все записи этой
вершины, а не одну.
