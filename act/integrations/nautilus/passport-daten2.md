## Почему уровня 3 оказалось недостаточно

Паспорт писался по схеме v1.2 и упёрся в неё на первом же поле.

`native_unit` — «что является атомарной единицей хранения». У daten2 атомарная
единица — **не документ и не концепт, а действие**: `POST /api/orders` создаёт
обязательство в мире. Ни один из семи допустимых типов `PortalEntry`
(`document`, `concept`, `rule`, `theory`, `schema`, `archetype`, `conversation`)
этого не выражает.

Проверка по тексту PORTAL-PROTOCOL.md v1.2 (17 разделов):

| слово | вхождений |
|---|---:|
| `verb` | 0 |
| `execute` | 0 |
| `invoke` | 0 |
| `perform` | 0 |
| `mutate` | 0 |
| `consent` | 0 |

Уровень 3 «Interactive» требует `fetch() queries live data source` — это живое
**чтение**. Магазин, который принимает заказ, подключить этим нечем.

Отсюда расширение [NPP-Act 1.0](https://github.com/svend4/daten2/blob/main/act/SPEC-NPP-ACT.md)
и уровень 4 (Actionable). Оно ничего не ломает в v1.2: уровни 0–3 остаются как
есть, добавляется измерение «последствие».

## Что объявляет глагол

Четыре поля, которых нет ни в OpenAPI, ни в gRPC, ни в GraphQL — потому что
они описывают форму вызова, а агенту нужно последствие:

| Вопрос агента | Поле |
|---|---|
| Что это изменит в мире? | `effect` ∈ {read, reserve, commit, money, destroy} |
| Можно ли это отменить? | `reversible` / `reverse` |
| Сколько это стоит и чьих денег? | `cost` |
| Нужен ли здесь человек? | `consent` ∈ {none, notify, confirm, two_party} |

## Что требует уровень 4

Репозиторий уровня 4 **MUST**:

1. публиковать валидный манифест (`GET /.well-known/npp-act.json`);
2. для каждого глагола с `effect` ≠ `read` объявить `consent` и обратимость;
3. вести персистентный журнал исполнений;
4. отвергать вызовы без ключа идемпотентности там, где он объявлен.

Репозиторий уровня 4 **SHOULD** также удовлетворять уровню 2 (адрес Q6), чтобы
его глаголы были findable наравне со знанием — что этот адаптер и делает.

## Q6-координата

Адрес глагола **вычисляется из последствия**, не курируется:

```
b5 b4 b3  эффект (тяжесть, монотонно)
          000 read · 001 reserve · 010 commit · 011 money · 100 destroy
          101 110 111 — зарезервировано под будущие эффекты
b2        необратимость: 0 обратим (объявлен reverse) · 1 необратим
b1 b0     согласие: 00 none · 01 notify · 10 confirm · 11 two_party
```

Единица всегда означает «тяжелее», поэтому число единиц в адресе растёт вместе
с риском. Примеры из настоящих манифестов:

| Адрес | Глагол | Чтение адреса |
|---|---|---|
| `000100` | `flower-shop.catalog.list` | read, необратим (нечего отменять), без согласия |
| `001000` | `freelance-guild.quote.request` | reserve, обратим, без согласия |
| `010110` | `flower-shop.order.create` | commit, необратим, нужно подтверждение |
| `010011` | `freelance-guild.contract.sign` | commit, обратим, согласие обоих |
| `011110` | `freelance-guild.payment.release` | money, необратим, нужно подтверждение |
| `111111` | `npp_act:spec` | зарезервированная тяжесть + необратимость + оба: предельная точка, ради охраны которой расширение существует |

Две честные оговорки.

**Первая.** Биты `b5..b3` — двоичное число, а не код Грея. Расстояние Хэмминга
внутри этого поля нельзя читать как семантическую близость: `001` (reserve) и
`011` (money) отличаются одним битом, но двумя шагами тяжести. Для упорядочивания
по риску надо брать `severity`; соседство по Хэммингу означает «тот же профиль
последствия с точностью до одной оси».

**Вторая.** Это другая проекция, чем в §9.2 v1.2, где `b5b4` — класс CA.
NPP-Act занимает то же 64-вершинное пространство, но кладёт в него другую
сущность. §9.3 это прямо разрешает («Each adapter defines a rule mapping its
native entities to Q6»). Совпадение адреса глагола с адресом концепта —
**коллизия по §9.4, а не тождество**: `glyph`-читателю нельзя выводить из
равенства адресов равенство смыслов.

Из 64 вершин глаголу доступны 40 (5 эффектов × 2 обратимости × 4 согласия);
24 вершины с `severity ≥ 101` зарезервированы и настоящим глаголом не
занимаются никогда.

## Тип записи: `action` с деградацией к `document`

Адаптер отдаёт записи о глаголах с `format_type = "action"`. Это не нарушение
v1.2: §4.1 сам оставил дверь открытой — «Implementations MAY define additional
values. Unknown values MUST be treated as `document`».

Ставить `document` по умолчанию было бы ложью. Читатель, который видит
`document`, вправе считать запись безопасной для показа и пересказа, а запись
о глаголе `money` безопасной не является. Для читателей старше v1.2, не
исполняющих требование о деградации, есть явный режим: `NppActAdapter(degrade=True)`
ставит `document` в `format_type` и **сохраняет правду** в
`metadata["format_type"] = "action"`. Потеря информации при деградации обязана
быть восстановимой, иначе это подмена, а не деградация.

Запись о манифесте сервиса имеет тип `schema` — существующий и точный: манифест
действительно является схемой, только не данных, а последствий.

## Что репозиторий даёт экосистеме

| Вклад | Где |
|---|---|
| Контракт действия из 4 глаголов | `openapi.yaml` в семи уровневых ветках (байт-в-байт идентичны) |
| Семь взаимозаменяемых исполнителей | `claude/level1-php` … `claude/level7-enterprise` |
| Гейт действий агента | `act/npp_act/governor.py` — 8 жёстких + 4 мягких предиката |
| Журнал решений с хэш-цепью | `act/npp_act/ledger.py` |
| Единственная дверь действия | `act/gateway.py` — за ней гейт стоит всегда |
| Измеренный профиль вместо заявленного | `act/npp_act/prober.py` — пять живых проб |
| Переносимая репутация | `act/npp_act/credential.py` — рекомендательное письмо вместо звёздочек |

Это и есть ответ на вопрос, зачем магазину цветов 32 сервиса ИИ-надстройки:
они написаны не для магазина. Они — **слой удержания для экосистемы, где
ИИ действует от имени человека**. Магазин был рабочей нагрузкой, на которой
этот слой отлаживался.

## Как получить данные

| Шаг | Что происходит |
|---|---|
| 1 | живой сервис: `GET {base_url}/.well-known/npp-act.json` — читается **объявление**, не действие |
| 2 | локальные файлы `act/manifests/**/*.act.json` (или путь из `NPP_ACT_MANIFESTS`) |
| 3 | вкомпилированный минимум с `is_fallback=true` (§4.4: адаптер MUST вернуть непустой список) |

Токенов не требуется. Адаптер **не вызывает ни один глагол** и физически не
умеет этого делать: единственный HTTP-запрос, который он делает, — чтение
манифеста. Исполнять глагол вправе только рантайм NPP-Act, где стоят губернатор
и журнал (`act/gateway.py`).

## Чего в репозитории нет (честно)

- Контракт v1 **не покрывает** смену статуса, отмену и возврат — заказ навсегда `new`.
- `discount` и `delivery_fee` объявлены в схеме и всегда равны нулю.
- Уровни 6 и 7 контракт держат **не полностью**: 7/22 и 15/22 при живом прогоне.
- Сервис заведения (`act/services/venue`) отдаёт на `/.well-known/npp-act.json`
  **404**: путь к файлу манифеста считается на один каталог выше нужного.
  Адаптер это переживает (падает к локальному файлу), но уровню 4 сервис в этой
  точке не удовлетворяет — починка на стороне сервиса, не адаптера.
- `compatibility: 4` выходит за `maximum: 3` действующей `passport_schema.json`.
  Схему нужно поднять до 4 — это одна строка, см. `APPLY.md`.
