# Паспорт репозитория: `svend4/daten2`

> Паспорт по схеме [Nautilus Portal Protocol v1.2 §7](https://github.com/svend4/nautilus/blob/main/PORTAL-PROTOCOL.md),
> расширенный до [NPP-Act 1.0](../SPEC-NPP-ACT.md) — уровень совместимости 4.

```json
{
  "repo": "svend4/daten2",
  "format": "daten2-act",
  "native_unit": "Глагол контракта (capability)",
  "compatibility": 4,
  "description": "Один магазин цветов в семи реализациях за единым REST-контрактом плюс слой удержания ИИ-агента.",
  "total_items": "4 глагола × 7 реализаций",
  "q6_key": "уровень 1..7 → младшие три бита; эффект глагола → старшие три",
  "act_manifest": "act/manifests/flower-shop.act.json"
}
```

## Почему уровня 3 оказалось недостаточно

Паспорт писался по схеме v1.2 и упёрся в неё на первом же поле.

`native_unit` — «что является атомарной единицей хранения». У daten2 атомарная
единица — **не документ и не концепт, а действие**: `POST /api/orders` создаёт
обязательство в мире. Ни один из семи допустимых типов `PortalEntry`
(`document`, `concept`, `rule`, `theory`, `schema`, `archetype`, `conversation`)
этого не выражает.

Проверка по тексту спецификации v1.2 (17 разделов):

| слово | вхождений |
|---|---:|
| `verb` | 0 |
| `execute` | 0 |
| `invoke` | 0 |
| `perform` | 0 |
| `mutate` | 0 |
| `consent` | 0 |

Уровень 3 «Interactive» требует `fetch() queries live data source` — это живое
**чтение**. Магазин, который принимает заказ, подключить этим нечем.

Отсюда расширение NPP-Act и уровень 4 (Actionable). Оно ничего не ломает в
v1.2: уровни 0–3 остаются как есть, добавляется измерение «последствие».

## Что repo даёт экосистеме

| Вклад | Где |
|---|---|
| Контракт действия из 4 глаголов | `openapi.yaml` в семи уровневых ветках (байт-в-байт идентичны) |
| Семь взаимозаменяемых исполнителей | `claude/level1-php` … `claude/level7-enterprise` |
| Гейт действий агента | `claude/twin-governor` → обобщён в `act/npp_act/governor.py` |
| Журнал решений с хэш-цепью | `claude/ops-ledger` → обобщён в `act/npp_act/ledger.py` |
| Защита входа агента | `claude/agent-firewall` |
| Протокол переговоров агент↔агент | `claude/agent-market` |
| Атомарный расчёт между агентами | `claude/a2a-settlement` |
| Сертификация новых бэкендов | `claude/plugin-marketplace` |

Это и есть ответ на вопрос, зачем магазину цветов 32 сервиса ИИ-надстройки:
они написаны не для магазина. Они — **слой удержания для экосистемы, где
ИИ действует от имени человека**. Магазин был рабочей нагрузкой, на которой
этот слой отлаживался.

## Чего в репозитории нет (честно)

- Контракт v1 **не покрывает** смену статуса, отмену и возврат — заказ навсегда `new`.
- `discount` и `delivery_fee` объявлены в схеме и всегда равны нулю.
- Уровни 6 и 7 контракт держат **не полностью**: 7/22 и 15/22 при живом прогоне.
- Персистентность в слое ИИ отсутствует почти везде — именно поэтому
  `act/npp_act/ledger.py` написан заново, с записью на диск.
