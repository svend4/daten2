# NPP-Act — расширение протокола Nautilus: уровень совместимости 4

**Версия:** 1.0
**Статус:** Draft
**Расширяет:** [Nautilus Portal Protocol v1.2](https://github.com/svend4/nautilus/blob/main/PORTAL-PROTOCOL.md)
**Лицензия:** CC BY 4.0

Ключевые слова **MUST**, **MUST NOT**, **REQUIRED**, **SHOULD**, **SHOULD NOT**,
**MAY**, **RECOMMENDED** употребляются в значении BCP 14 (RFC 2119, RFC 8174).

---

## 0. Зачем это нужно

NPP v1.2 федерирует **знание**. Его собственный абстракт говорит прямо:
«The protocol adds a shared **read layer** on top».

Это подтверждается словарём протокола. Все допустимые типы записи —
`document`, `concept`, `rule`, `theory`, `schema`, `archetype`, `conversation`.
Слова `verb`, `execute`, `invoke`, `perform`, `mutate`, `consent` в тексте
спецификации **не встречаются ни разу**.

Уровень совместимости 3 называется «Interactive», но его требование —
`fetch() queries live data source`, то есть **живое чтение**, а не действие.

Следствие: репозиторий, который **что-то делает** (принимает заказ, резервирует
время, переводит деньги), подключить к Наутилусу сегодня нечем. Библиотека
живая, но не действующая.

NPP-Act добавляет недостающее измерение — **уровень 4, Actionable** — не ломая
ничего из v1.2. Репозиторий уровня 4 удовлетворяет всем требованиям уровней 0–3
и дополнительно объявляет **глаголы**.

---

## 1. Главная идея: описывать не форму, а последствие

OpenAPI, gRPC и GraphQL описывают **форму** вызова: путь, метод, типы.
Этого достаточно программисту и недостаточно автономному агенту.

Чтобы агент мог решить, **вправе ли он это сделать**, ему нужны четыре вещи,
которых нет ни в одной из перечисленных схем:

| Вопрос агента | Поле NPP-Act |
|---|---|
| Что это изменит в мире? | `effect` |
| Можно ли это отменить? | `reversible` / `reverse` |
| Сколько это стоит и чьих денег? | `cost` |
| Нужен ли здесь человек? | `consent` |

**NPP-Act — это схема последствий, а не схема вызова.** Форму он берёт из
существующей спецификации (`binding.openapi`), а добавляет ровно то, что
нужно для принятия решения о допустимости действия.

---

## 2. Термины

| Термин | Значение |
|---|---|
| **Actionable-сервис** | Репозиторий/сервис, публикующий манифест возможностей |
| **Манифест** (`*.act.json`) | Документ, объявляющий глаголы сервиса |
| **Глагол** (capability) | Одна объявленная операция с описанными последствиями |
| **Губернатор** (governor) | Компонент, допускающий или блокирующий глагол до исполнения |
| **Журнал** (ledger) | Append-only хэш-цепь намерений, решений и исходов |
| **Обязательство** (commitment) | Двустороннее соглашение двух профилей, записанное в оба журнала |

---

## 3. Манифест возможностей

Actionable-сервис **MUST** публиковать манифест по пути `/.well-known/npp-act.json`
либо объявлять его в реестре Наутилуса полем `act_manifest`.

```json
{
  "npp_act": "1.0",
  "service": "flower-shop",
  "title": "Магазин цветов",
  "base_url": "http://127.0.0.1:8181",
  "profile": "vendor",
  "capabilities": [ { "...": "глагол" } ]
}
```

| Поле | Тип | Обяз. | Значение |
|---|---|:--:|---|
| `npp_act` | `"1.0"` | MUST | версия расширения |
| `service` | string | MUST | идентификатор сервиса |
| `base_url` | string | MUST | корень HTTP-привязки |
| `profile` | enum | MUST | `person` · `vendor` · `venue` · `institution` · `broker` |
| `capabilities` | array | MUST | не менее одного глагола |

## 4. Глагол

```json
{
  "id": "order.create",
  "title": "Оформить заказ",
  "effect": "commit",
  "reversible": false,
  "cost": { "money": "variable", "currency": "EUR", "time_s": 1 },
  "consent": "confirm",
  "idempotency": "header:Idempotency-Key",
  "binding": { "protocol": "http", "method": "POST", "path": "/api/orders" },
  "input": { "name": "string", "items": "array" },
  "output": { "order_number": "string", "total": "number" }
}
```

### 4.1. `effect` — что глагол делает с миром

Значение **MUST** быть одним из пяти. Порядок строго по возрастанию тяжести:

| `effect` | Значение | Пример |
|---|---|---|
| `read` | ничего не меняет | `GET /api/products` |
| `reserve` | удерживает ресурс временно, истекает сам | удержание слота на 15 минут |
| `commit` | создаёт обязательство | оформление заказа, бронь |
| `money` | двигает деньги | оплата, возврат |
| `destroy` | уничтожает состояние необратимо | удаление аккаунта |

Агент **MUST** считать, что тяжесть монотонна: разрешив `money`, он разрешил и
`read`. Обратное неверно.

### 4.2. `reversible` и `reverse`

Если `reversible` = `true`, глагол **MUST** объявить `reverse` — идентификатор
обратного глагола того же сервиса.

```json
{ "id": "slot.hold", "effect": "reserve", "reversible": true, "reverse": "slot.release" }
```

**Правило проектирования:** предпочитать пару `reserve` → `commit` одиночному
`commit`. Удержание обратимо, обязательство — нет. Это даёт агенту право
попробовать, не нанеся ущерба. Практически это означает:
**любой многошаговый сценарий MUST начинаться с обратимых шагов.**

### 4.3. `cost`

```json
"cost": { "money": "variable" | number, "currency": "EUR", "time_s": 1 }
```

`"variable"` означает, что сумма становится известна только из ответа. Губернатор
**MUST** в этом случае требовать либо предварительной оценки (`estimate`), либо
потолка (`max_money` во входе), либо подтверждения человека.

### 4.4. `consent` — участие человека

| `consent` | Требование |
|---|---|
| `none` | агент действует сам |
| `notify` | агент действует и уведомляет постфактум |
| `confirm` | требуется подтверждение владельца профиля **до** исполнения |
| `two_party` | требуется согласие **обоих** профилей, оформленное обязательством (§7) |

### 4.5. `idempotency`

Глагол с `effect` ∈ {`commit`, `money`} **MUST** объявить способ идемпотентности
(`header:<имя>` или `field:<имя>`) либо явно указать `"idempotency": "none"`,
признав риск двойного исполнения. Губернатор **MUST** блокировать повтор глагола
с тем же ключом.

## 5. Губернатор: допуск действия

Исполнитель **MUST NOT** вызывать глагол с `effect` ≠ `read`, минуя губернатора.

Губернатор возвращает одно из трёх решений: `admit`, `block`, `escalate`.

### 5.1. Жёсткие предикаты (нарушение → `block`)

1. **Неизвестный сервис.** Сервиса нет в реестре.
2. **Неизвестный глагол.** Глагола нет в манифесте сервиса.
3. **Превышение бюджета.** Объявленная или оценённая стоимость выше остатка бюджета.
4. **Необратимое обязательство без согласия.** `effect` ∈ {`commit`, `money`,
   `destroy`}, `reversible` = `false` и `consent` = `none`.
   Предикат **MUST** ограничиваться обязательствами. Применённый ко всем
   эффектам, он блокирует и откат: отпускание удержания формально необратимо
   («отменить отмену» нельзя), но лишь возвращает мир в прежнее состояние.
   Запрет на откат делает систему опаснее, а не безопаснее — агент теряет
   способность убирать за собой.
5. **Отсутствие идемпотентности.** `effect` ∈ {`commit`, `money`} без ключа.
6. **Повтор.** Ключ идемпотентности уже встречался в журнале.
7. **Просроченное удержание.** `commit` ссылается на истёкшую резервацию.

### 5.2. Мягкие предикаты (нарушение → `escalate`)

1. Стоимость выше порога эскалации (по умолчанию 50% остатка бюджета).
2. `cost.money` = `"variable"` без потолка во входе.
3. `consent` ∈ {`confirm`, `two_party`} и подтверждения ещё нет.
4. Сервис ни разу не встречался в журнале (первое взаимодействие).

### 5.3. Безопасная альтернатива

При `block` губернатор **SHOULD** предложить альтернативу, если она выводима:
заменить `commit` на парный `reserve`, понизить количество до бюджета,
разбить действие на обратимые шаги.

---

## 6. Журнал: хэш-цепь решений

Каждая запись:

```json
{
  "seq": 3,
  "ts": "2026-10-09T12:00:00Z",
  "kind": "decision",
  "payload": { "...": "..." },
  "prev": "e3b0c44298fc1c14…",
  "hash": "a7f5f35426b927411f…"
}
```

`hash` = SHA-256 от канонического JSON `{seq, ts, kind, payload, prev}`.
Первая запись имеет `prev` = 64 нуля.

Виды записей **MUST** включать: `intent`, `decision`, `execution`, `outcome`,
`commitment`.

Журнал **MUST** быть персистентным. Журнал решений ИИ, живущий в оперативной
памяти, не является журналом: он не переживает перезапуск и не может быть
предъявлен как доказательство.

---

## 7. Двустороннее обязательство (`two_party`)

Это то, чего нет ни в одном товарном протоколе, и ради чего существует
расширение: **действие, в котором участвуют два независимых профиля**, и оба
несут ответственность.

Протокол из четырёх шагов:

```
1. offer    — инициатор объявляет намерение (обратимо, effect=reserve)
2. hold     — принимающая сторона удерживает ресурс и возвращает срок
3. accept   — обе стороны подтверждают (consent обеих сторон получен)
4. commit   — обязательство фиксируется в ОБОИХ журналах
```

Запись `commitment` **MUST** содержать общий `commitment_id` и хэши записей
обеих сторон:

```json
{
  "commitment_id": "cmt_7f3a…",
  "parties": ["person:anna", "venue:clinic-nord"],
  "hashes": { "person:anna": "a7f5…", "venue:clinic-nord": "9c2d…" }
}
```

Проверяющий **MUST** иметь возможность, имея оба журнала, убедиться, что обе
стороны записали одно и то же обязательство. Ни одна сторона не может изменить
свою запись, не разорвав собственную цепь.

Если шаг 3 не наступил до истечения удержания, инициатор **MUST** вызвать
обратный глагол удержания. Ресурс не должен залипать из-за несостоявшейся сделки.

## 8. Уровень совместимости 4

Дополняет лестницу NPP v1.2 §8:

| Уровень | Имя | Требование |
|---|---|---|
| 0 | Discoverable | запись в `nautilus.json` |
| 1 | Readable | статический список `PortalEntry` |
| 2 | Linked | координаты Q6 + перекрёстные ссылки |
| 3 | Interactive | живое чтение из внешнего источника |
| **4** | **Actionable** | **манифест глаголов + губернатор + журнал** |

Репозиторий уровня 4 **MUST**:
1. публиковать валидный манифест;
2. для каждого глагола с `effect` ≠ `read` объявить `consent` и обратимость;
3. вести персистентный журнал исполнений;
4. отвергать вызовы без ключа идемпотентности там, где он объявлен.

Репозиторий уровня 4 **SHOULD** также удовлетворять уровню 2 (адрес Q6), чтобы
его глаголы были findable наравне со знанием.

## 9. Отношение к n8n и подобным оркестраторам

NPP-Act **не заменяет** оркестратор и не конкурирует с ним. Разделение ролей:

| Слой | Чем является | Кто |
|---|---|---|
| Каталог | что существует и что с чем совместимо | **Наутилус** |
| Последствие | что произойдёт, если это вызвать | **NPP-Act** |
| Исполнение | как это вызвать и связать в цепочку | n8n, Temporal, свой рантайм |
| Удержание | вправе ли агент это вызывать | **губернатор + журнал** |

Оркестратор читает манифесты как каталог узлов. Слой удержания остаётся
обязательным независимо от выбора оркестратора.

---

## 10. Безопасность

1. Манифест — это **заявление**, а не доказательство. Потребитель **MUST**
   проверять поведение, а не верить полю. (В экосистеме уже есть образец такой
   проверки: `plugin-marketplace` — живой гейт соответствия контракту.)
2. Публичным **MUST** быть только манифест. Журнал содержит историю действий
   владельца и **MUST NOT** публиковаться вместе с паспортом.
3. Идентификаторы обязательств **MUST** быть непубличными токенами, а не
   инкрементными номерами (как `order_number` в контракте daten2).
4. Губернатор **MUST** быть неотключаемым для `effect` ∈ {`money`, `destroy`}.
